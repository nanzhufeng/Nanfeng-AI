# 南枫 AI Desktop 对话优先 UI 合同

日期：2026-08-13  
状态：统一 chat-first shell 已实现；2026-09-03 已按当前 Android owner 校正 C-01 空画布、C-02 内容画布与 C-03 侧栏层级，真实 Provider、同步及隔离 Tauri 内容态仍分层待验

## 当前增量：输入高度与动作图标

- Composer 文本区由 `composer-size.mjs` 按真实 scrollHeight 测量，最小 36px、上限 190px，超限内部滚动；输入、清空与恢复草稿共用该 owner，底部按钮保持独立一行。
- 收藏／取消收藏使用 Bookmark／BookmarkBorder，同步使用 CloudUpload，置顶与取消置顶共用 PushPin；20 个共享动作来自 AndroidX Material Rounded 原始路径，生成入口为 `sync-android-action-icons.py`。未转换图标仍须逐项核对，不能声称全量一致。

## 1. 最终视觉来源

- 用户确认来源：本轮提供的 ChatGPT Desktop 主对话、侧栏底部账号菜单，以及 ChatGPT/Codex 产品切换菜单截图。
- 采用的是成熟的信息架构：轻量侧栏、会话为第一入口、中央单一对话画布、固定输入区、低频能力进入菜单。
- 不复制 ChatGPT/Claude 的品牌、Logo、订阅、邀请、宠物、具体文案或账号业务；南枫 AI 使用自己的图标、领域状态和安全边界。
- 排除来源：当前 P6-D 默认三栏知识工作台、工程 Inspector 首屏、历史开发探针、静态 fixture 作为默认首页。
- 视觉冲突优先级：用户最新明确方向 > 南枫 AI 领域与安全事实 > 本合同 > 既有 P6-D 布局。

## 2. 第一用户任务与入口矩阵

第一用户任务是：打开 Desktop 后立即开始或继续一次对话；空白／新会话也必须能先选择 Auto 或具体模型，点击“发送”时把新会话、模型选择、user message 与 Attempt 作为同一 Rust SQLite 事务提交。Provider 未启用或凭据不可用时保留明确失败 Attempt，不把“模型可选择”误写成“Provider 已配置”。用户可随时切到工作模式管理本地资产，但不会离开同一浅色壳或失去返回对话的路径。

FB-P6-025 进一步锁定：本壳不是工程模块入口的视觉重排，而是意图优先入口。空态的画布与唯一 Composer、对话态的按需附件/来源/metadata/回底、drawer 的 search/pinned/recent 与底部 Settings、以及 USER/Assistant 的角色投影，必须分别证明意图进入、渐进揭示、持久治理和消息语义；详见 `CHAT_FIRST_INTENT_ORGANIZATION_CONTRACT.md`。

### 2.1 统一外壳的权威解释（2026-08-13）

- `对话 / 工作` 是真实模式切换，始终位于同一顶部栏；不是装饰标签，也不启动第二套页面架构。
- 对话模式左侧依次承载品牌、搜索、定时任务、南枫转写、会话历史，并在底部保留彼此独立的设置与新对话浮动控件；右侧承载当前对话与输入区。
- 工作模式进入、再次点击“工作”或切换工作区后，右侧默认必须是该工作区最近一次对话；没有会话时显示该工作区的新对话空态和同一输入区。工作区是当前对话的 scope，不得把 work-home、资产仪表盘或管理首页当默认右侧内容。
- 工作模式在同一左侧区域切换为工作区、项目、知识、记忆和本地受控记录；只有明确点击项目、知识、记忆或记录时，才替换右侧对话为对应二级管理页。知识与记忆是独立入口，不能在一个固定混合清单里同时铺开。
- 两种模式共用浅色侧栏、顶部栏、账号/设置入口、尺寸、token、焦点和明确返回路径；禁止加载或暴露深绿色 legacy workbench、固定 Inspector 或第二套导航。
- 输入区主动作固定为“发送”，本地消息、会话与草稿默认自动保留。空白／新会话的模型选择先作为本机 draft 状态保存，第一次发送时由 `submit_desktop_ordinary_chat` 将会话、精确模型、user message 与 Attempt 原子提交；已有会话的模型选择继续由会话 override owner 持久化。Provider 未配置时不读取 Key、不构造 Authorization、不请求网络，并保留可恢复的明确失败事实。

### 2.2 Composer 模型选择合同（2026-09-02）

- 模型选择入口与 Provider／API Key 就绪状态是两个独立事实。只要本地产品模型目录存在，空白／新会话必须显示实际 Auto 模型短名并保持入口可点击，禁止再以“未配置”替代模型目录。
- 根层只显示“自动／日常／深度”；日常与深度进入下一层完整候选列表。分组、候选顺序、全名与 Composer 短名跟随 Android 当前模型选择合同。
- 具体模型行的小字必须逐项读取当前 Android 模型目录中该 preset 的用户说明；不得显示 Provider ID、内部 family、路由键或其他工程标识。日常／深度二级页标题始终居中，标题下不重复显示分组泛化说明。
- P6-G 的 `LOCAL`／fixture 候选只属于自动化验收，不能进入用户可见候选、不能由 UI 安装，也不能以历史快照残留的形式漏进 Composer。
- Auto 不写精确模型 override；手动选择必须保存精确 preset ID。新会话在首次发送前允许修改选择，发送成功提交后清除 draft；发送前失败则保留选择和草稿供用户重试。
- 选择模型不代表 Provider、Key 或网络已经可用。真正发送时仍由模型服务 owner 做启用状态、凭据、外发与费用边界检查，禁止静默换模型或伪造成功。

| 概念 | 唯一所有者 | 主入口 | 二级入口 | 禁止项 |
| --- | --- | --- | --- | --- |
| 当前对话与消息 | Rust Desktop Conversation Domain | 左侧会话列表、中央画布 | 工作模式中的项目归属 | 首页同时展示 Knowledge/Memory/Inspector |
| 输入草稿 | Desktop Chat Shell 内存状态，未来接持久草稿合同 | 空态与内容态共用固定底部输入区 | 无 | 状态变化移动输入区、把空输入写入 SQLite |
| 本地/联网模型路径 | 双路径能力状态 owner | 输入区路径选择、设置 | 调用记录 | 把未配置写成“离线产品终态”或假装联网成功 |
| Project/Knowledge/Memory/relation | 既有 Rust Domain | 顶部“工作”模式 | 对话内按需引用 | 在默认聊天首屏铺开完整工作台 |
| 模型、账号、同步、本地数据 | 各自既有领域 owner | 侧栏底部设置 | 专用设置页 | 在首页堆状态卡或让一个总开关扩大外发范围 |
| Agent/P8/生态审计 | 既有只读 ledger / 合同 owner | 高级设置或工作模式 | 详情 | 作为一级导航抢占普通用户视线 |

## 3. 目标视口

| 形态 | 平台 | 类别 | 导航 | 页面结构 | 滚动所有者 |
| --- | --- | --- | --- | --- | --- |
| 唯一产品基准 | macOS/Windows 常规宽屏 | `1440×900` | 240–272px 常驻侧栏 | 侧栏 + 单一主画布 | 会话列表与消息列表各自滚动 |
| 防溢出验证 | macOS/Windows 较小窗口 | `1000×800`、`700×900` | 必要时收起为可恢复 drawer | 与宽屏相同的信息架构 | 消息列表 |

`1440×900` 是唯一产品视觉基准；较小窗口只验证同一信息架构没有溢出，不构成紧凑版、第二套产品层级或新的对外截图基准。宽屏仍一次只显示一个一级模式。既有 Inspector 不再作为统一 shell 的并排或默认入口；安全状态通过当前工作功能页和设置的最小必要信息呈现。

紧凑侧栏的关闭控件不是常驻导航：常规宽度完全不渲染/显示；仅在 `< 900px` 且 drawer 已打开时，在侧栏右上角显示小型 `×` 图标按钮，保留 `aria-label="关闭导航"` 而不显示“关闭”文字。点击它只关闭 `sidebarOpen`，不得改变当前对话/工作模式、workspace、conversation 或正在查看的二级页。

## 4. 视觉令牌

- 页面与主画布：`#FFFFFF`；侧栏：低饱和浅灰 `#F5F6F4`。
- 普通浮层/菜单：`#FFFFFF`；描边：`#E3E5E2`；不使用彩色模块卡片。
- 文字：`#202522`；辅助文字：`#6C746F`。
- 主结构/选中：南枫绿 `#176B52`，只用于小面积状态与关键动作。
- 联网等待/注意：橙色；错误：红色；不得用颜色替代文字状态。
- 圆角：侧栏功能行约 9–12px、搜索与底部动作使用胶囊形，Composer 外层 28px、普通浮层 14–18px。
- 阴影仅用于输入容器和浮层；主页面不套大型卡片或多层边框。

## 5. 页面空间顺序

### 聊天模式（默认）

- 侧栏：品牌 → 搜索 → 定时任务 → 南枫转写 → 分组会话列表 → 底部设置胶囊／新对话胶囊。底部只绘制两个独立浮动表面，不得加硬边白色托盘或紫色状态胶囊。
- 主区：轻量顶部栏 → 安静空画布或当前消息列表 → 固定底部 Composer。
- 空态不显示 Hero 图形、欢迎标题或持久化实现说明；空态与内容态共用同一底部 Composer。进入已有会话只切换顶部动作与消息滚动 owner，不移动 Composer。
- 消息溢出只滚动消息列表，侧栏会话列表独立滚动。

### 工作模式（工作区范围内的对话优先）

- 通过顶部“对话 / 工作”明确切换；两个切换在任何工作功能页始终可见可用。两种模式的默认右侧内容都是对话，不存在工作模式 dashboard 首页。
- 左侧按当前模式显示对应功能集；工作区切换当前 Conversation scope，并立即选中该 scope 最近会话；无会话时保留新对话空态。项目、知识、记忆和本地受控记录都在同一浅色 shell 的右侧内容面内按需运行。
- 可复用既有 Project/Knowledge/Memory/relation、撤销/重做、导入导出与只读 P8 能力，但不保留其深色三栏/Inspector 外壳。

### 设置与账号

- 由侧栏底部菜单进入。
- 模型 Provider、API Key 存在性、目录新鲜度、逐次外发确认、账号加密同步分别展示，不合并成一个“联网”总开关。
- 未配置时统一显示“联网未配置，本地可用”；不得显示假账号、假服务成功或假费用。

## 6. 状态矩阵

| 状态 | 用户可见文案 | 操作 | 持久化/恢复 |
| --- | --- | --- | --- |
| 本地发送 | 原子记录会话、模型选择、user 与 Attempt | 新会话可先选 Auto／具体模型再发送 | Rust SQLite transaction/revision |
| Provider 未就绪 | 模型仍可选择；本地记录保留，回答明确失败 | 打开模型设置或改选已启用服务 | 不读取缺失 Key、不发 HTTP、不静默换模型 |
| 已配置待确认 | 将发送给明确 Provider/Model，费用可能产生 | 逐次确认 | Consent 只绑定本次请求 |
| 联网运行 | 正在等待/生成，停止可用 | 停止 | 由 Invocation/Event owner 持久化 |
| 联网失败 | 中文原因与下一步，本地内容保留 | 重试、换模型或继续本地 | 新 Invocation，不覆盖旧事实 |
| 同步未配置/冲突 | 本地真值可用；同步未配置/需处理 | 账号与同步设置 | P7 状态机与账本 |

## 7. 交互与动效

- 聊天/工作和会话切换即时完成，无整页淡入或滑动。
- 空态、已有会话和普通状态切换均保持同一底部 Composer 锚点；焦点态只在 Composer 内展开编辑区与底部动作行，不移动其页面级 owner。
- 回车发送、Shift+Enter 换行；空白拒绝。失败或取消保留输入和已有消息。
- 侧栏底部设置胶囊进入设置页；不得再出现第二个账号菜单或遮挡全屏的工程 Dialog。
- 低频项目、知识、同步、审计不增加一级导航；通过工作模式或设置进入。
