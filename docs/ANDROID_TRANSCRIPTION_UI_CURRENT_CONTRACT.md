# Android 南枫转写当前界面合同

> 适用范围：`Nanfeng_AI` 的“南枫转写”当前产品能力。当前事实以 `GlmOcrWorkspace.kt`、`GlmOcr.kt` 和对应 JVM 合同为准；本文不把历史 Desktop 语音转写或另一个 App 的能力反向写入当前 Android。

## 当前产品边界

- 一级入口固定为侧栏“南枫转写”，打开全屏工具页，标题为“南枫转写”，右上关闭返回原会话。
- 当前创建入口只接受图片或 PDF，底部主按钮固定为“选择图片或 PDF”。Android 当前没有录音入口，也不创建音频／视频任务。
- 旧 Desktop 音频／视频任务可以只读兼容，但必须与当前 GLM-OCR 任务分组，不能恢复新建、设置或重试入口。
- GLM-OCR 固定使用自身 Provider owner，不进入聊天模型选择，不静默切换模型。

## 可见状态与动作

| 状态 | 必须可见的事实 | 允许动作 |
| --- | --- | --- |
| 空态 | 单一画布、“还没有转写结果”、“从底部选择图片或 PDF 开始。” | 选择图片或 PDF、关闭返回 |
| 待确认 | 原始文件、文件名／类型／大小、页数／Token／费用未返回、Attempt／请求数 | App 内预览原文件、开始转写、继续选择 |
| 处理中 | “等待处理／正在转写／正在保存”之一，以及“离开页面后任务仍会继续。” | 关闭返回；后台 owner 继续持久化 |
| 失败／需恢复 | 持久任务、用户可理解的失败提示、安全错误码、Attempt、请求数和请求 ID 事实 | 重新转写、删除任务、关闭返回 |
| 完成 | 原始文件、页数、Token、Attempt、请求数／ID、估算费用、Markdown 文件和正文 | App 内预览结果、复制、TXT／MD／DOCX 导出、加入新对话、删除任务、关闭返回 |

## Owner 与持久化

- 文件选择只返回路径；Rust／Android domain owner 校验类型和大小、复制到私有内容寻址附件区、写入持久任务后，UI 才显示“待确认”。
- 原始图片／PDF和结果 Markdown 复用会话、搜索与草稿的共享附件 owner；本地文件只在 App 内预览，不回退第三方查看器。
- 任务状态、失败、用量和结果必须落入 SQLite／Room。离开页面或重启后仍能回读；未知结果不得静默重发。
- Browser 只读状态夹具只用于布局与交互 QA，必须明确标注不写 Desktop SQLite、不读文件字节、不调用 Provider。

## Desktop 适配

- Desktop 转写入口先显示页面及读取状态，再异步读取本机任务；重复点击合并同页读取，离开页面后迟到结果不能触发当前页重绘或覆盖其错误。读取中不显示“没有转写结果”的确定空态。

- 整个转写页面支持拖入 JPG、PNG、PDF；复用文件选择的本地导入与待确认任务 owner，不自动调用识别服务。

- Desktop 宽屏可以把任务列表和详情做成双栏，但空态仍是单画布，底部橙色主按钮不放入白色托盘，也不能因 Browser 预览而灰掉。
- 详情可以显示更多持久事实和键鼠 hover／focus，但入口、状态文字、主动作、失败恢复与返回层级不得平台分叉。
- `1440×900` 是产品视觉验收视口；较窄窗口只验证防溢出，不产生第二套紧凑产品 IA。

## 完成门槛

1. 行为合同覆盖空态、待确认、处理、失败、完成和返回，并锁定无录音入口。
2. Browser 同视口实看上述状态、至少一次“选择 → 待确认 → 开始 → 处理中”交互，控制台无 warning／error。
3. Android JVM／构建与 Desktop Node／Rust／bundle 分层通过。
4. 隔离 Tauri 用唯一 bundle ID、唯一 `/tmp` 数据根和诊断模式完成真实系统文件选择、私有预览、SQLite 入库及重启回读；不得读取正式数据根或 Provider 凭据。
5. 真实 Provider 的成功输出、服务端失败与账单事实属于独立外部验收；没有该证据时必须明确写“未验收”。
