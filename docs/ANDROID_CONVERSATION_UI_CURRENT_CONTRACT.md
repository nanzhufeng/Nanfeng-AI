# 南枫 AI Android 当前会话与搜索界面合同

日期：2026-08-26
状态：**当前有效；2026-08-26 用户反馈与 OPPO 覆盖结果已收敛；Android 会话、抽屉、Composer、搜索与暗色皮肤的唯一视觉／交互正文**

## 1. 范围、优先级与不可回退项

本合同约束 Android `ConversationWorkspace` 的会话画布、顶部切换、左侧栏、Composer、模型选择、消息页脚、文本选中和全屏搜索。它只定义用户可见结构与交互；Provider 外发、凭据、模型路由、费用、导入导出、对话与附件数据 owner 仍以其领域合同为准。普通聊天的个性化、Memory 与资料库上下文只读 [Android 当前运行时上下文合同](ANDROID_RUNTIME_CONTEXT_CURRENT_CONTRACT.md)。

发生冲突时，优先级固定如下：

1. 本合同：当前会话、抽屉、Composer、搜索、皮肤和图标的可见规则。
2. `ANDROID_SETTINGS_UI_CURRENT_CONTRACT.md`：设置及其子页的可见规则。
3. 各领域合同：真实数据、路由、Provider、费用、导入、隐私和生命周期语义。
4. 历史实施／验收文档：仅可作证据，**不得**重新提供颜色、尺寸、弹窗、卡片、模型文案或手势规则。

尤其不得回退为：静态橙色、黑色描边、浮动标签、抽屉底部白色托盘、在 Composer 显示完整厂商模型名、把设置弹窗当作默认导航方式，或在暗色皮肤保留浅色表面／黑色文字。

## 2. 全局视觉令牌与皮肤

### 2.1 共同原则

- 所有可交互表面、阴影、按压／水波纹、焦点与选中态必须使用同一个圆角或胶囊轮廓；禁止圆角控件配矩形阴影或黑色线框。
- 浅色皮肤：页面是略压暗的中性灰，真正前景（卡片、按钮、输入框、弹层）是纯白 `#FFFFFF`。前景不可再用近白灰伪装，也不画黑边。
- 暗色皮肤：所有一级至四级画布、抽屉、搜索、对话与弹层共享同一套深炭灰层级；最深画布介于纯黑与卡片灰之间，禁止大面积纯黑。前景卡为中深灰，不使用白卡；正文／标题为高对比白色，辅助文字为浅灰。Markdown 表格使用深炭表面、稍亮表头、深色复制控件与可见分隔线；音频预览使用深色播放器及半透明白色操作胶囊，禁止保留白色圆控件或固定浅蓝播放器。任意路由切换不得出现深浅跳闪。
- 主题色由“外观”统一提供。所有开关、选中胶囊、保存、发送、进度、强调图标、选中文字背景和光标／拖拽手柄都从该令牌取色，禁止遗留橙色常量。用户消息气泡使用同主题的**低饱和、偏灰、比当前页面底色更暗**的派生色，不等同于高饱和强调色。
- 普通按钮文字在浅色为清晰黑色；暗色为清晰白色。placeholder 比正式输入内容明显更浅。
- 全部应用图标采用圆端、圆角、近 Q 版的轮廓语言；会话相关图标使用近圆的对话气泡和圆角尾巴。不得用尖锐、过黑或手绘替代图标。系统状态栏／导航栏图标也要随皮肤维持可读对比。

### 2.2 层级与阴影

- 会话／工作画布、抽屉、搜索和设置各有语义 surface，但同一皮肤内必须复用同一组令牌，不能各自写近似色。
- 前景不以描边区分，只以底色、留白和极柔和的环境阴影区分。顶部浮动控件与 Composer 使用同轮廓的柔和阴影；Composer 比顶部更重，但不得硬边、黑晕或额外托盘。
- **当前冻结阴影基线：** 顶部浮动圆钮／操作胶囊、普通／工作／临时侧栏的设置圆钮，以及普通侧栏的新对话胶囊，统一使用 `dropShadow`（`54dp` 半径、`0x1B000000`、向下 `3dp`）。Composer 独用同形状的对称 `dropShadow`（`84dp` 半径、`1dp` 扩散、`0x22000000`、`DpOffset.Zero`）。这是当前已确认效果；不得回退为 platform elevation shadow，不得用仅增大 elevation 或旧的 `8/12/18/28/36/56dp` 半径、`0x26/0x31` 透明度和 Composer 向下 `5dp` 偏移替代它。
- 一键到底按钮必须是与 Composer 同一外层、在 Composer 之后绘制的覆盖层；只把 `zIndex` 写在正文内层不能跨父层，视为不满足本合同。Composer 阴影只能落在画布上，绝不可压暗、染色或遮挡该按钮。按钮自身的圆形表面、阴影与按压反馈仍共用同一形状。
- 对话层级固定为：正文／Composer < 一键到底 < 所有对话内弹层。模型选择面、Composer 左侧“添加”面及其遮罩共用高于一键到底的弹层令牌；原生 `Popup`／`Dialog` 作为独立窗口同样必须在其之上。弹层打开时，一键到底不得穿透、遮挡或接收点击。
- 单行白色控件（按钮、输入框、单行设置入口、搜索框、切换项）一律胶囊；多行内容卡才可用较大圆角矩形。

## 3. 顶栏、会话画布与正文

- 顶栏悬浮在画布之上；正文通过可滚动 inset 避开，不得增加静态白／灰安全条或把整页下推。
- 空对话可显示居中的“对话／工作”切换；非空对话保留既有真实导航结构。深色皮肤中，选中“对话／工作”的文字为纯白。
- Composer 单独消费导航栏和 IME 安全区，并随键盘整体上移；正文末端使用可滚动 inset，确保最后一条消息可完整越过 Composer 阅读。不得用根 padding 或固定底栏填充解决。
- 日期分隔线在同一会话内始终使用统一的低对比中性分隔色；背景压暗后不得变成白线。
- 长内容的顶部／底部渐变只作用于实际 transcript 像素，连续过渡、无硬边，不得形成整块雾带、灰幕或静态底条。
- 滚动进度条不得遮挡正文或超出安全区；可滚动内容初始与滑动中立即显示，画面静止 `3` 秒后自动隐藏；无可滚动内容时隐藏。
- 内外屏／尺寸变化只重排，不重建会话或重置阅读锚点、草稿、路由或生成状态。
- 系统长截图只允许当前可见 transcript 作为候选；关闭但仍在 Compose 树中的抽屉不得参与 capture。截图期间暂停自动回底和仅用于屏幕观感的边缘遮罩。

## 4. 左侧栏、会话列表与滑动操作

### 2026-08-27 侧栏滚动视口修正（本节优先）

- 普通抽屉顶部出现横跨全宽、边界笔直的白／灰条，或列表文字被同一水平线截断时，按滚动视口裁切诊断，不当作独立背景层删除。`verticalScroll` 必须在 `statusBarsPadding`／内容顶部 padding **之前**建立；推荐顺序为 `fillMaxSize → conversationEdgeGrayFade(edgeColor = ConversationDrawerBaseSurface) → verticalScroll → statusBarsPadding → content padding`。
- 渐变是滚动视口自身的无命中绘制，使用连续抽屉基底色以自然淡出；不得加独立全屏 sibling `Box`、硬边灰／白托底或透明化搜索、“已计划”等正常卡面。固定品牌行是无底色 overlay，列表通过可滚动 inset 为它留位。

- 抽屉是导航画布，不是整张白色前景卡。浅色抽屉从状态栏到导航栏连续使用亮白基底，`ModalDrawerSheet` 不得叠加 tonal elevation 或再铺一层硬边灰底；抽屉本身必须实绘该基底穿过透明系统状态栏，不能依赖系统默认底色；不得在顶部或底部露出小块白条。深色皮肤沿用深炭灰基底。**“硬边遮挡灰底／灰卡”包括覆盖在软件名上方、边界清楚的任意灰色矩形承托面，必须完全删除。与之不同，浅色滚动列表继续使用 `#F2F2F2` 的上下软渐变加强遮盖：内容在两端自然淡入／淡出，渐变层无命中、无硬边，必须固定在实际滚动列表的可视窗口内，不跟随内容滚动；其窗口从固定应用标题下方开始，并位于标题和底部控件之下。顶部渐变仅加强遮盖强度（完整端 `1.00`、中段 `0.90 / 0.62 / 0.22`），范围继续固定为 `128dp`；底部范围 `112dp` 与原强度不变。**普通对话抽屉的顶部应用图标和“南枫 AI”从状态栏安全区下方开始排布，不能占用系统状态栏；它们是独立、固定且高于滚动列表的悬浮层，滚动时不移动，不加白底、灰卡或托盘，也不受其他画布层遮挡。搜索、“已计划”、设置与新对话是各自的前景控件；搜索和“已计划”共用比抽屉基底更深一阶的中性灰表面，搜索图标与文字作为整体居中，搜索与“已计划”文字均使用正文色以保持清晰。抽屉内容不得绘制顶部或底部的硬边白底承托层或安全条；列表、图标和标题始终直接呈现在连续抽屉基底上，浮动设置／新对话控件保持清晰。设置圆钮和新对话胶囊按第 2.2 节复用顶部浮层阴影，阴影、可见表面、按压与命中反馈分别服从它们自身的圆形／胶囊轮廓，不改变颜色、尺寸或业务行为。
- 抽屉是导航画布，不是整张白色前景卡。浅色抽屉从状态栏到导航栏连续使用亮白基底，`ModalDrawerSheet` 不得叠加 tonal elevation 或再铺一层硬边灰底；抽屉本身必须实绘该基底穿过透明系统状态栏，不能依赖系统默认底色；不得在顶部或底部露出小块白条。深色皮肤沿用深炭灰基底。**“硬边遮挡灰底／灰卡”包括覆盖在软件名上方、边界清楚的任意灰色矩形承托面，必须完全删除。与之不同，浅色滚动列表继续使用 `#F2F2F2` 的上下软渐变加强遮盖：内容在两端自然淡入／淡出，渐变层无命中、无硬边，必须固定在实际滚动列表的可视窗口内，不跟随内容滚动；其窗口从固定应用标题下方开始，并位于标题和底部控件之下。顶部渐变仅加强遮盖强度（完整端 `1.00`、中段 `0.90 / 0.62 / 0.22`），范围继续固定为 `128dp`；底部范围 `112dp` 与原强度不变。**普通对话抽屉的顶部应用图标和“南枫 AI”从状态栏安全区下方开始排布，不能占用系统状态栏；它们是独立、固定且高于滚动列表的悬浮层，滚动时不移动，不加白底、灰卡或托盘，也不受其他画布层遮挡。抽屉标题、搜索／已计划、会话行及其信息图标与主界面正文均按当前“小／标准／大”比例缩放；只放大可见文字和图标，标题预留高度同步增长，触控面、卡片和页面几何不随之扩大。搜索、“已计划”、设置与新对话是各自的前景控件；搜索和“已计划”共用比抽屉基底更深一阶的中性灰表面，搜索图标与文字作为整体居中，搜索与“已计划”文字均使用正文色以保持清晰。抽屉内容不得绘制顶部或底部的硬边白底承托层或安全条；列表、图标和标题始终直接呈现在连续抽屉基底上，浮动设置／新对话控件保持清晰。设置圆钮和新对话胶囊按第 2.2 节复用顶部浮层阴影，阴影、可见表面、按压与命中反馈分别服从它们自身的圆形／胶囊轮廓，不改变颜色、尺寸或业务行为。
- 已置顶与最近可分组；会话标题和日期均单行紧凑显示。会话标题使用与主界面正文一致的 `16sp / 20sp / Normal` 标准字级，标题太长时省略，不能为标题增加第二行。顶部“搜索”与“已计划”也统一使用相同的 `16sp / 20sp` 标准基线。置顶及“对话管理”采用相同的圆润对话气泡图标。
- 批量编辑的选择框只显示 `16dp` 方框、`4dp` 圆角和 `1.5dp` 描边；未选为克制中性描边，选中为主题色底与 `12dp` 白色对勾。直接命中面为透明 `32dp`，整条 `52dp` 会话行仍可切换选择；不得恢复 Material 默认的大方框、粗描边或扩大可见轮廓。
- 会话列必须能够继续滚到悬浮设置／新对话按钮之上，末项不得被遮挡；末端空白只能是随列表滚动的 inset。普通与批量行分别以 `36dp`／`44dp` 收紧标题文字上下呼吸，卡片之间现有的 `8dp` 间距不变。
- 右滑会话操作、已归档／回收站的左滑操作遵循同一规则：只在手势后出现；点红色删除区才执行删除；点操作带外的同一行、其他行、空白区或同级控件时只收起操作带，绝不误触发导航、恢复或删除。
- “已归档”和“回收站”是独立入口。列表项为紧凑单行标题加**创建时间**，不显示“已归档／已移入回收站”等重复小字，也不用归档／删除时间替代创建时间。恢复与删除经滑动操作带提供；回收站删除为永久操作，需明确确认。
- 新 Assistant 内容到达而该会话未打开时，列表可显示主题色未读点；阅读后清除。新建普通会话完成开头一问一答后，仅将该两段文本发送给已配置的 Qwen3.7-Plus，严格生成“讨论对象 + 任务／结论方向”的 6–32 字标题；禁止从回答小节、局部结论或用户首句本机截取。失败则保留“新对话”，不写残句；手动重命名优先且永不被异步结果覆盖。标题整理不发送附件、后续对话或个性化资料，调用记录只留 Token／费用等安全元数据。
- “已计划”是独立全屏计划入口，不混入会话列表正文；其搜索与选中控件使用压暗的胶囊表面，无黑边。

## 5. Composer、模型名与文本选择

- 未聚焦 Composer 保持紧凑单行预览，长草稿单行省略。点击文字区域后，在控制行**上方**展开完整宽度的多行编辑区；附件、模型与发送仍留在底部功能行，输入内容不得挤在这些控件之间。失焦或 IME 收起时都必须在同一帧直接选择单行渲染，不能先保留多行再等待焦点副作用；已输入草稿必须保留。焦点态编辑区上方固定保留 `10dp`，最小可编辑高度为 `28dp`（只容纳一条真实文字，不在文字下方预留额外半行），最长内容才可扩至 `208dp` 并在内部滚动；底部附件／模型／发送功能行固定 `60dp`。不得缩小该功能行、让文字进入右侧发送区域，或恢复焦点态 `36dp` 的多余下缘空白。
- 附件加号为圆端、圆润笔画，视觉大小与命中面协调，不得过长、尖角或再套方形底。附件菜单文字与图标是纯黑色，保证清晰。菜单最底部固定提供与设置一致的主题色地球图标及“实时网页搜索”开关，不另用“当前对话联网”名称，也不显示重复小字；首次进入继承设置中的全局“实时网页搜索”值，切换后只持久覆盖当前普通会话、不中断草稿且不改全局默认或其他会话。它复用现有白色浮层、主题色与胶囊开关轮廓，不新增 Composer 常驻按钮。
- Composer 只显示短模型名，例如 `5.6 Sol`、`Sonnet 5`、`Opus 5`；不得显示厂商、Provider、路由或模型 ID。模型选择面、模型设置、调用／费用／上下文记录及需要精确识别模型的消息页脚，使用目录中的完整具体模型名；模型选择面可显示完整名称，不得被 Composer 的短名规则误覆盖。
- 主界面的模型选择小卡与侧栏会话长按菜单属于短暂选择面：其中的标题、选项与说明文字统一使用主界面同档字号的 `90%` 紧凑密度，仍完整跟随“小／标准／大”；不缩小菜单行高、图标、卡片或触控面。侧栏会话列标题单独使用 `14sp / 18sp` 基线，略大于其日期并按全局字号档位缩放。
- Assistant 回复页脚在完整模型名之后显示该请求金额：OpenRouter 返回的 `usage.cost` 是权威值，合法的 `$0.00` 必须保留；只在无法取得权威值时，当前目录中的每个模型按版本化本机价目表显示带 `≈` 的 token-only 估算，历史 token-only 记录也即时补算。估算不包含响应未披露的联网工具、优惠或缓存写入费用。**主界面页脚仅投影金额本身：不显示 `≈` 或“估算”，每笔金额以 `HALF_UP` 四舍五入并固定显示四位小数；这不改写领域数据、费用与用量页、设置或任何估算标识。**时间、模型和金额放得下时保持一行；屏幕或字体缩放导致放不下时，金额必须另起一行靠右显示，禁止逐字符竖排、截断金额或挤压操作图标。费用汇总、币种换算、幂等和 fallback 的真实规则由费用合同定义。
- 用户在“个性化”明确启用并填写昵称后，新对话首个成功 Assistant 回复必须先以该昵称自然称呼用户；规则在 OpenRouter、千问、DeepSeek、自动路由与比较模式的共用正常聊天请求层生效。用户在当前消息明确要求别的称呼时，以当前要求为准；后续回复不强制重复称呼。
- 手动选择具体模型后必须持续使用该模型；`Auto` 才可自动路由。可见名、实际调用与记录归因不得互相伪造。
- 所有输入框的选中背景、光标和拖拽手柄统一使用主题色（背景可用主题色透明度），不能残留系统青绿／固定橙色。

## 6. 模型选择面、短暂面板与消息动作

- 模型选择可作为与 Composer 直接相关的短暂选择面；点击遮罩关闭，子层先返回上层，再关闭根层。不得把它扩展为设置页的通用弹窗模式。
- 模型候选显示完整、稳定、可辨识的目录名称；完整弹层内容须可见且可滚动，不能以圆形小弹窗裁掉信息。
- Assistant 页脚及复制、分享、分支等动作遵循紧凑、圆润、无黑边的图标语言。分享是现有分享能力；不得再新增重复的“导出当前对话／导出文本会话”入口。
- 联网能力不与“深度档”绑定：所有档位、所有模型按当前 Provider 能力享有同样的联网开关／调用路径；普通发送优先采用当前会话的联网覆盖值，未覆盖时才继承设置全局值。无法联网时必须如实显示，不得默默降级或假称已联网。

## 7. 全屏搜索与本地预览

- 搜索是独立全屏页，包含严格居中的顶部“搜索”标题、范围 tabs、结果区与底部搜索栏／历史入口；不复用设置弹窗或抽屉白底。浅色皮肤的搜索页画布为较深灰白 `#EDEEEE`，底部搜索输入框与“历史”按钮为再深一阶的 `#E1E4E2`，文件／结果卡保持纯白，三者必须清晰分层；深色皮肤使用对应深灰层级。结果区在底部搜索框／历史入口下方复用主界面的底部同色软渐变加强，内容自然淡出；渐变只在结果与控件之间绘制，不得成为搜索框或历史按钮的硬边承托底。
- 深色搜索必须完整消费深色令牌：画布、tabs、选中态、结果卡、缩略图承托、底部输入栏和历史按钮均不留白色残片或黑色文字。图片、视频与文档缩略图保留其真实内容颜色，外层承托采用中性 surface。
- 浅色搜索的结果与输入表面为纯白、无黑边；深色结果卡为前景炭灰、文字高对比白。分类的选中填充和波纹沿用主题色与同一圆角。
- 搜索结果中的音频缩略图／列表徽标是深色语义播放器，浅色皮肤用深蓝灰、深色皮肤用深炭灰；播放图标、格式和时间线保持白色并与承托面有清晰对比，禁止把它们绘制在普通浅色缩略图底上。
- 搜索附件普通点击直接在当前搜索页之上打开完整本地预览，不得先跳转到对话；长按才出现“跳转到对应对话”。此操作只有一个选项，必须以锚定在被长按文件附近的紧凑单操作卡片菜单呈现，不得使用带标题、文件名、确认／取消的居中模态对话框。结果卡、文件卡、文件行、历史胶囊和会话行的按压／选中／波纹必须裁剪到与自身白卡、胶囊或圆角行完全相同的轮廓，禁止直角矩形选区外溢。
- 标准对话框通过共享 Dialog owner 支持点击空白处关闭；留有周围空白的自定义卡片弹窗也必须铺设可点击的透明 backdrop。音频预览卡点击卡片外的空白处关闭并保存当前本地播放位置；全屏图片、PDF、视频预览保留其明确的关闭控件，不把媒体内容误判为“空白区域”。
- 搜索索引、时间、附件类型、安全预览、搜索历史和真实数据边界由 `P6F2_UNIFIED_SEARCH_HISTORY_AND_LOCAL_CONTENT_PREVIEW_CONTRACT.md` 负责；本合同覆盖其中所有 Android 搜索的视觉数值与皮肤表现。

## 8. 文字阅读与消息内容

- 正文、标题、列表、表格、引用、代码、来源 chip 与附件仍按其语义呈现；模型近似 Markdown 的明确格式错误须在内存投影中归一化：行内标题井号转为独立标题、缺空格标题补齐、可识别的两／三反引号代码围栏转为代码块、紧贴文本的列表前缀转为列表。孤立的反引号、井号、列表星号与来源分隔符不直接呈现；来源只有有效 http(s) 链接时才显示入口，禁止“主要参考：、 、 、”等占位噪声。深色皮肤同步提供可读的正文／次要文字／分隔线，不得出现黑字、白卡或高饱和硬边。
- 用户气泡在浅、深皮肤中均比背景更易分辨，但保持低饱和主题派生色；不使用纯主题高饱和块，也不因长文本变成椭圆／圆形。
- 本地来源、上下文或联网资料不得通过空白卡、伪成功状态或无意义小字占位。必要状态要有用户可理解的事实；冗余解释性小字应删除。

## 9. 验收门

- 自动检查至少覆盖：主题切换下无硬编码橙色；浅色前景白／无黑边；暗色文本白／多层画布同色；冻结阴影参数及其接收控件；一键到底在 Composer 外层之后绘制；Composer 短名与其他精确名称分流；焦点多行编辑区的 `10dp / 28dp / 60dp` 分工与发送区隔离；选中颜色；滑出操作点外收起；侧栏末项可上移；归档／回收站创建时间及删除；搜索全皮肤覆盖。
- 视觉验收需覆盖浅色和深色的空对话、长对话、打开键盘、左侧栏、搜索五分类、已归档／回收站；构建或安装只能证明各自层级，不能替代真实观感与手势。
