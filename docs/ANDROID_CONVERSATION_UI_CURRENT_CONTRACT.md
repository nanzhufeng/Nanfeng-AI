状态：**当前有效；已纳入对话级风格／联网覆盖、回答级执行证据与短模型名规则；Android 会话、抽屉、Composer、搜索与暗色皮肤的唯一视觉／交互正文**

## 1. 范围、优先级与不可回退项

- 会话列表日期固定读取创建时间并按本机时区显示，不使用最后回复／同步更新时间。Android 自动预建空白会话在首次正式发送时确定创建时间；后续回复、改名、置顶不改创建时间。旧空白占位记录只凭本机原始根用户消息及同期发送记录校正，并排除导入／恢复来源；证据不足保持原值，不按标题或当前时间猜日期。

本合同约束 Android `ConversationWorkspace` 的会话画布、顶部切换、左侧栏、Composer、模型选择、消息页脚、文本选中和全屏搜索。它只定义用户可见结构与交互；Provider 外发、凭据、模型路由、费用、导入导出、对话与附件数据 owner 仍以其领域合同为准。普通聊天的个性化、Memory 与资料库上下文只读 [Android 当前运行时上下文合同](ANDROID_RUNTIME_CONTEXT_CURRENT_CONTRACT.md)。

发生冲突时，优先级固定如下：

1. 本合同：当前会话、抽屉、Composer、搜索、皮肤和图标的可见规则。
2. `ANDROID_SETTINGS_UI_CURRENT_CONTRACT.md`：设置及其子页的可见规则。
3. 各领域合同：真实数据、路由、Provider、费用、导入、隐私和生命周期语义。
4. 历史实施／验收文档：仅可作证据，**不得**重新提供颜色、尺寸、弹窗、卡片、模型文案或手势规则。

尤其不得回退为：静态橙色、黑色描边、浮动标签、抽屉底部白色托盘、在 Composer 显示完整厂商模型名、把设置弹窗当作默认导航方式，或在暗色皮肤保留浅色表面／黑色文字。

### 普通启动与短时恢复

- 普通图标启动默认进入新对话；只有退出记录完整且间隔小于 15 分钟时，恢复退出时实际选中的会话及其对话／工作 surface。缺少 ID、时间异常、会话已删除或归档时进入新对话，禁止按抽屉首项或置顶排序选择启动会话。旧版本仅有退出时间的记录不视为可恢复记录。
- 退出时存在生成任务则保留退出工作区的连续性；进程重建只回读持久状态，不自动补发。明确的会话快捷方式、分享与深链继续由各自入口处理。
- 新对话草稿恢复与一小时清理遵守 [新对话草稿保留合同](NEW_CONVERSATION_DRAFT_RETENTION_CONTRACT.md)；旧“有草稿不能复用”规则已被用户新要求替代。配置变化不计为退出。

## 2. 全局视觉令牌与皮肤

### 2.1 共同原则

- 所有可交互表面、阴影、按压／水波纹、焦点与选中态必须使用同一个圆角或胶囊轮廓；禁止圆角控件配矩形阴影或黑色线框。
- 浅色皮肤：页面是略压暗的中性灰，真正前景（卡片、按钮、输入框、弹层）是纯白 `#FFFFFF`。前景不可再用近白灰伪装，也不画黑边。
- 暗色皮肤：所有一级至四级画布、抽屉、搜索、对话与弹层共享同一套深炭灰层级；最深画布介于纯黑与卡片灰之间，禁止大面积纯黑。前景卡为中深灰，不使用白卡；正文／标题为高对比白色，辅助文字为浅灰。Markdown 表格使用深炭表面、稍亮表头、深色复制控件与可见分隔线；音频预览使用深色播放器及半透明白色操作胶囊，禁止保留白色圆控件或固定浅蓝播放器。任意路由切换不得出现深浅跳闪。
- 主题色由“外观”统一提供。所有开关、选中胶囊、保存、发送、进度、强调图标、选中文字背景和光标／拖拽手柄都从该令牌取色，禁止遗留橙色常量。用户消息气泡使用同主题的**低饱和、偏灰、比当前页面底色更暗**的派生色，不等同于高饱和强调色。
- 普通按钮文字在浅色为清晰黑色；暗色为清晰白色。placeholder 比正式输入内容明显更浅。
- 全部应用图标采用圆端、圆角、近 Q 版的轮廓语言；会话相关图标使用近圆的对话气泡和圆角尾巴。不得用尖锐、过黑或手绘替代图标。系统状态栏／导航栏图标也要随皮肤维持可读对比。

### 2.2 层级与阴影

- 会话／工作画布、抽屉、搜索和设置各有语义 surface，但同一皮肤内必须复用同一组令牌，不能各自写近似色。
- 前景不以描边区分，只以底色、留白和极柔和的环境阴影区分。顶部浮动控件与 Composer 使用同轮廓的柔和阴影；Composer 比顶部更重，但不得硬边、黑晕或额外托盘。
- **当前冻结阴影基线：** 顶部浮动圆钮／操作胶囊、普通／工作／临时侧栏的设置胶囊，以及普通侧栏的新对话胶囊，统一使用 `dropShadow`（`54dp` 半径、`0x1B000000`、向下 `3dp`）。Composer 独用同形状的对称 `dropShadow`（`84dp` 半径、`1dp` 扩散、`0x22000000`、`DpOffset.Zero`）。这是当前已确认效果；不得回退为 platform elevation shadow，不得用仅增大 elevation 或旧的 `8/12/18/28/36/56dp` 半径、`0x26/0x31` 透明度和 Composer 向下 `5dp` 偏移替代它。
- 一键到底按钮必须是与 Composer 同一外层、在 Composer 之后绘制的覆盖层；只把 `zIndex` 写在正文内层不能跨父层，视为不满足本合同。Composer 阴影只能落在画布上，绝不可压暗、染色或遮挡该按钮。按钮自身的圆形表面、阴影与按压反馈仍共用同一形状。
- 顶部“一键到顶”与底部“一键到底”共用同一浮层组件和真实滚动边界，均不是常驻控件：画面停止滚动满 **3 秒**后自动隐藏；只有用户手动向下阅读时立即显示底部按钮，用户手动向上阅读时立即显示顶部按钮。手势惯性滚动属于同一次手动阅读，会持续刷新这 3 秒计时；程序自动跟随、流式更新或发送引发的滚动不得擅自显示任何按钮。顶部按钮还要求列表**真实可继续向上滚动**，其圆心与菜单按钮位于同一顶部行；短按向上一整可见阅读屏，长按直达真实开头并保持关闭自动跟随。底部按钮还要求列表**真实可继续向下滚动**，不能因长篇 Assistant 回复作为单个 `LazyColumn` item 露出顶部就提前消失；短按每次按当前可见阅读区的一整屏高度向下推进（`LazyList` viewport 减去底部 Composer 覆盖高度），绝不按固定 dp、消息、回复或段落定位；中途可连续点击，最后一次必须被滚动容器自然钳制到“再也拉不动”的真实末端，届时才隐藏；长按是明确的“直达最新消息”，必须直接抵达真实末端并恢复自动跟随。自动跟随补底时只能抵达真实末端，绝不可 `scrollToItem(最后一项)` 把长末项顶部对齐而反跳上方。用户手指拖动一开始就必须取消自动跟随；新消息临时令列表可继续向下滚动不等于用户离开底部，不能据此关闭跟随或触发回顶。用户自行抵达真实末端后才可恢复后续新消息跟随。
- 对话层级固定为：正文／Composer < 一键到底 < 所有对话内弹层。模型选择面、Composer 左侧“添加”面及其遮罩共用高于一键到底的弹层令牌；原生 `Popup`／`Dialog` 作为独立窗口同样必须在其之上。弹层打开时，一键到底不得穿透、遮挡或接收点击。
- 胶囊形状只用于单行白色控件／卡片（按钮、输入框、单行设置入口、搜索框、切换项）；多行内容卡、说明面、确认弹层及长文本承载面一律使用圆角矩形（通常 `24dp`），不得以 `999dp` 胶囊轮廓拉成椭圆。

## 3. 顶栏、会话画布与正文

- 顶栏悬浮在画布之上；正文通过可滚动 inset 避开，不得增加静态白／灰安全条或把整页下推。
- 空对话可显示居中的“对话／工作”切换；非空对话保留既有真实导航结构。深色皮肤中，选中“对话／工作”的文字为纯白。
- Composer 单独消费导航栏和 IME 安全区，并随键盘整体上移；正文末端使用可滚动 inset，确保最后一条消息可完整越过 Composer 阅读。不得用根 padding 或固定底栏填充解决。
- 日期分隔线在同一会话内始终使用统一的低对比中性分隔色；背景压暗后不得变成白线。
- 长内容的顶部／底部渐变只作用于实际 transcript 像素，连续过渡、无硬边，不得形成整块雾带、灰幕或静态底条。
- 滚动进度条不得遮挡正文或超出安全区；可滚动内容初始与滑动中立即显示，画面静止 `3` 秒后自动隐藏；无可滚动内容时隐藏。
- 内外屏／尺寸变化只重排，不重建会话或重置阅读锚点、草稿、路由或生成状态。
- 普通对话的真实生成任务归属具体会话与前台服务，不归属当前 Compose 页面。生成期间允许切换其他对话、对话／工作界面、搜索、设置及其他应用内页面；这些导航动作只切换 UI 投影，绝不取消、重启或重复发送原请求。返回原对话时必须从 Room 恢复已持久化增量、当前运行态和停止入口。进入后台前存在生成任务时，回到应用不得自动创建新对话覆盖原工作区；进程被系统终止后只显示持久恢复／未知态并由用户显式重试，禁止自动补发。
- 系统长截图只允许当前可见 transcript 作为候选；关闭但仍在 Compose 树中的抽屉不得参与 capture。截图期间暂停自动回底和仅用于屏幕观感的边缘遮罩。

## 4. 左侧栏、会话列表与滑动操作

### 2026-08-27 侧栏滚动视口修正（本节优先）

- 普通抽屉顶部出现横跨全宽、边界笔直的白／灰条，或列表文字被同一水平线截断时，按滚动视口裁切诊断，不当作独立背景层删除。`verticalScroll` 必须在 `statusBarsPadding`／内容顶部 padding **之前**建立；推荐顺序为 `fillMaxSize → conversationEdgeGrayFade(edgeColor = ConversationDrawerBaseSurface) → verticalScroll → statusBarsPadding → content padding`。
- 渐变是滚动视口自身的无命中绘制，使用连续抽屉基底色以自然淡出；不得加独立全屏 sibling `Box`、硬边灰／白托底或透明化搜索等正常卡面。“定时任务”按本节使用无底色导航行，不得再包灰色胶囊。固定品牌行是无底色 overlay，列表通过可滚动 inset 为它留位。

- 抽屉是导航画布，不是整张白色前景卡。浅色抽屉从状态栏到导航栏连续使用亮白基底，`ModalDrawerSheet` 不得叠加 tonal elevation 或再铺一层硬边灰底；抽屉本身必须实绘该基底穿过透明系统状态栏，不能依赖系统默认底色；不得在顶部或底部露出小块白条。深色皮肤沿用深炭灰基底。**“硬边遮挡灰底／灰卡”包括覆盖在软件名上方、边界清楚的任意灰色矩形承托面，必须完全删除。与之不同，浅色滚动列表继续使用 `#F2F2F2` 的上下软渐变加强遮盖：内容在两端自然淡入／淡出，渐变层无命中、无硬边，必须固定在实际滚动列表的可视窗口内，不跟随内容滚动；其窗口从固定应用标题下方开始，并位于标题和底部控件之下。顶部渐变仅加强遮盖强度（完整端 `1.00`、中段 `0.96 / 0.76 / 0.36`），范围继续固定为 `128dp`；底部范围 `112dp` 与原强度不变。**普通对话抽屉的顶部应用图标和“南枫 AI”从状态栏安全区下方开始排布，不能占用系统状态栏；它们是独立、固定且高于滚动列表的悬浮层，滚动时不移动，不加白底、灰卡或托盘，也不受其他画布层遮挡。搜索、“定时任务”、设置与新对话是各自的前景控件；搜索保留比抽屉基底更深一阶的中性灰胶囊并整体居中，“定时任务”直接位于抽屉画布，使用左对齐的圆形时钟图标与名称，不绘制常态背景。两者文字和图标均使用正文色。抽屉内容不得绘制顶部或底部的硬边白底承托层或安全条；列表、图标和标题始终直接呈现在连续抽屉基底上，浮动设置／新对话控件保持清晰。设置圆钮和新对话胶囊按第 2.2 节复用顶部浮层阴影，阴影、可见表面、按压与命中反馈分别服从它们自身的圆形／胶囊轮廓，不改变颜色、尺寸或业务行为。

- 普通、工作和临时侧栏底部的设置胶囊共用同一个中性图标规则：胶囊为独立固定的 `108dp × 48dp`，齿轮居中且只使用当前正文色，浅色皮肤为正常黑色，深色皮肤为可读白色，不再消费强调色或其派生色。普通侧栏“新对话”恢复按图标、文字和按钮内边距自然测量的原有胶囊，不与设置宽度建立比例、共享常量或相互参与测量；调整设置尺寸不得压缩、换行或移动“新对话”。三种设置入口继续共用白色前景面、冻结阴影、`48dp` 命中面、胶囊按压轮廓和设置路由。本条替代上文所有“设置圆钮”及其圆形轮廓的历史描述。
- 普通左侧栏顶部“南枫 AI”是固定品牌标题，使用 Android `sans-serif-rounded` 的 `22sp / 28sp / Bold`，图标同步为 `36dp`。滚动列表在顶部必须预留图标与标题行高中的较大值；默认状态下首个搜索／定时任务控件不得被品牌行遮挡。它只改变品牌行，不改变会话标题、日期、行高或底部悬浮控件。
- 已置顶与最近可分组；会话标题和日期均单行紧凑显示。标题右侧日期固定读取对话创建时间，不得因新增消息、重命名、置顶或其他更新改成最新修改时间；列表“最近”排序仍按现有最新更新时间规则，不与日期展示字段混用。长按菜单的“未读”是本机持久、可反复设置的手动未读提醒：标记后的会话优先排到它所属分组的顶部，已置顶会话仍留在置顶区但排在其他置顶会话之前；多条手动未读会话按最近一次设置时间排序。该标记只改变同组优先级，不擅自置顶、收藏或归档。左侧栏会话标题使用 `14sp / 18sp / Normal` 标准字级，标题太长时省略，不能为标题增加第二行。顶部“搜索”与“定时任务”仍使用各自的 `16sp / 20sp` 标准基线。置顶及“对话管理”采用相同的圆润对话气泡图标。用户明确点击“新对话”时，必须创建新的普通会话、切回活跃列表，并按最新更新时间显示为“最近”的第一条；不得复用旧空白会话而保留其旧排序。置顶分组及其排序不受此动作影响。
- 批量编辑的选择框只显示 `16dp` 方框、`4dp` 圆角和 `1.5dp` 描边；未选为克制中性描边，选中为主题色底与 `12dp` 白色对勾。直接命中面为透明 `32dp`，整条 `52dp` 会话行仍可切换选择；不得恢复 Material 默认的大方框、粗描边或扩大可见轮廓。
- “最近”右侧批量编辑铅笔的可见图形为 `13.3dp`（相对原 `19dp` 缩小 30%），但仍保留 `36dp` 点击面和原有分组布局。
- 会话列必须能够继续滚到悬浮设置／新对话按钮之上，末项不得被遮挡；末端空白只能是随列表滚动的 inset。列表必须按可见视口惰性组合，禁止因切换批量编辑而同步组合全部历史会话。普通与批量行分别以 `36dp`／`44dp` 收紧标题文字上下呼吸，卡片之间现有的 `8dp` 间距不变。
- 右滑会话操作、收藏／已归档／回收站的左滑操作遵循同一规则：会话右滑带依次为置顶／取消置顶、收藏／取消收藏、重命名、删除，收藏紧跟置顶；收藏列表的“取消收藏”与归档／回收站的恢复、删除都只在左划后出现。点操作带外的同一行、其他行、空白区或同级控件时只收起操作带，绝不误触发导航、取消收藏、恢复或删除。
- 收藏、已归档和回收站的未滑出列表项都可直接打开对应真实会话；从该会话系统返回时必须回到刚才的原列表与滚动位置，不得回落到普通对话列表。归档／回收站列表项为紧凑单行标题加**创建时间**，不显示“已归档／已移入回收站”等重复小字，也不用归档／删除时间替代创建时间。恢复与删除经滑动操作带提供；回收站删除为永久操作，需明确确认。
- 新 Assistant 内容到达而该会话未打开时，列表可显示主题色未读点；手动标为“未读”也使用同一主题色圆点，但内部来源仍独立。圆点固定在会话标题左侧、文字正前方；置顶行顺序为“置顶图标 → 圆点 → 标题”，日期右侧不放点。两者同时存在只画一个圆点；点击真正进入该对话时同时完成阅读并清除手动未读标记，长按、滑动、弹出菜单或点其他行不得清除。手动未读会话在各自层级内优先：普通列表分别置于“已置顶”和“最近”顶部，工作列表置于所属项目内顶部；不跨分组改变归属。选中会话使用主题色浅底，左侧会话图标与标题文字同步切换为当前主题色；日期和其他辅助信息保持辅助色。新建普通会话完成开头一问一答后，自动标题与历史资料整理共用同一份固定顺序：只从已启用且有凭据的 `DeepSeek V4.1 Flash → GLM-5.3 Flash → Qwen3.6 Flash` 中依次选择，千问始终位于最后兜底；不调用 OpenRouter 或其他高价模型。标题严格生成“明确对象 + 具体意图／问题／任务”的 6–13 字符标题；原文术语优先，禁止“继续说”“总结”“更新文档”等无对象泛词。标题可由汉字、英文字母和阿拉伯数字组成，英文单词之间仅允许一个普通空格；禁止标点、emoji、Markdown、括号、连字符、下划线及其他符号。禁止从回答小节、局部结论或用户首句本机截取。首条仅含附件时，不读取或外发附件类型、文件名、内容或本体，只用南枫AI首条回复生成标题；服务暂不可用或格式不合格时保留自动资格，在后续完成回复时重试，绝不把“新对话”固化为最终标题。模型明确返回了非空但格式不合格的标题时，同一服务商最多追加一次格式纠正请求，仍不合格才进入下一已配置候选；空标题表示模型无法确认对象，不强迫补写。每次纠正必须独立计量与审计，不在本机截断或伪造标题；超时、网络未知和取消立即结束本轮，不自动转投下一服务商。Desktop 智谱标题请求显式使用 thinking enabled／reasoning_effort max，并为包含推理的输出提供 8192 Token 上限；非 DeepSeek 后台请求超时上限为 180 秒。输出达到 length 上限须记录 OUTPUT_LIMIT，不能误报为 JSON 格式错误。手动重命名优先且永不被异步结果覆盖。标题整理不发送后续对话或个性化资料，调用记录只留 Token／费用等安全元数据；无启用服务或缺少凭据时也要记录安全失败原因。
- 正在生成的普通会话在侧栏标题前显示紧凑主题色进度环；它与未读点来源独立，可同时存在，本条将组合顺序明确为“置顶图标 → 未读点 → 进度环 → 标题”。每个会话最多一个活动请求，多个会话可分别生成；切换后 Composer 只读取当前会话自己的运行态，“停止生成”只停止当前会话。系统通知不暴露标题或正文；存在多个活动会话时显示数量，通知中的批量停止必须明确写为“停止全部生成”。
- 用户消息保留 Markdown 的标题、段落、列表、引用、强调与代码语义，但采用独立且克制的气泡排版：正文 `15sp / 23sp / Normal`；三级标题仅为 `18sp / 17sp / 16sp`、行高 `26sp / 24sp / 23sp`，字重依次 `SemiBold / Medium / Medium`，不得使用 `ExtraBold` 或扩大页面级标题。列表正文 `15sp / 23sp`、项间距 `6dp`，注释 `13sp / 19sp`。南枫AI的开放阅读文档继续使用其现有更强层级（正文 `16sp / 25sp`、一级标题 `26sp / 35sp / ExtraBold`、列表项间距 `8dp`）；两套标准均随全局字体大小档位缩放，不改变气泡、阅读列或触控几何。
- “定时任务”是独立全屏计划入口，不混入会话列表正文；入口本身为无常态背景的时钟图标导航行，计划页内搜索与选中控件继续使用压暗的胶囊表面，无黑边。已计划页的“已计划”相对整页水平居中，关闭操作固定右侧，使用无文字、无边框的标准关闭图标并保留 `48dp` 命中面；关闭图标、系统返回、点外关闭统一回到会话页并直接展开左侧栏。删除标题下“按所选周期联网生成简报，可随时暂停或删除。”的重复说明，新建计划页保持原有左侧标题；编辑态“取消”只退回已计划列表，不退出整个入口。
- 当前 Android 定时任务的数据合同只包含任务名称、监控要求、每小时／每天周期、启用／暂停、下次时间和最近结果／错误；新建页默认名称为“新的监控”，隐私小字固定为“仅发送任务名称和监控要求，不发送完整对话或附件。”。当前 Android 没有单次、指定时间、每周、独立编辑入口或删除确认，验收与文档不得把这些 Desktop 扩展反写成 Android 事实。
- Desktop 对齐时复用同一全屏“已计划”层级、右侧关闭、紧凑通知控件、空态和橙色全宽创建按钮；允许在同一表单中保留本机 owner 已支持的单次／指定时间／每周、编辑和删除确认，但必须如实标为 Desktop 扩展。编辑／新建取消都回到已计划列表；手动新建后取消必须拒绝待处理草稿，不能在 SQLite 留下不可见计划。暂停态优先显示“已暂停，恢复后重新计算下次时间。”，不得继续呈现过期的下次执行事实。
- Browser 的 C-09 样本必须明确为“Web 只读交互样本不会写入 Desktop SQLite”，只用于结构、状态和交互回归；真实持久化只由隔离 Tauri／Rust owner 证明。通知开关可见不等于系统通知已投递，保存计划也不等于 Provider 已执行。
- “南枫转写”是独立全屏工具入口，固定紧跟“定时任务”之后，使用无常态背景的文档图标导航行与同规格命中面。页内顶部同步显示“南枫转写”并在可用宽度内居中。主页直接是全部转写列表，底部独立悬浮按钮选择图片／PDF；点击条目进入“可打开原文件 + 完整文字”详情。详情返回先回转写列表，列表页顶部返回、系统返回和边缘返回统一回到会话页并直接展开左侧栏。它不把 GLM-OCR 加入 Composer 模型选择、Auto 路由或定时任务模型候选；完整行为读取 [GLM-OCR 南枫转写当前合同](GLM_OCR_DOCUMENT_MARKDOWN_CONTRACT.md)。

## 5. Composer、模型名与文本选择

- 未聚焦 Composer 保持紧凑单行预览，长草稿单行省略。点击文字区域后，在控制行**上方**展开完整宽度的多行编辑区；附件、模型与发送仍留在底部功能行，输入内容不得挤在这些控件之间。失焦或 IME 收起时都必须在同一帧直接选择单行渲染，不能先保留多行再等待焦点副作用；已输入草稿必须保留。焦点态编辑区上方固定保留 `10dp`，最小可编辑高度为 `28dp`（只容纳一条真实文字，不在文字下方预留额外半行），最长内容才可扩至 `208dp` 并在内部滚动；底部附件／模型／发送功能行固定 `60dp`。不得缩小该功能行、让文字进入右侧发送区域，或恢复焦点态 `36dp` 的多余下缘空白。
- Composer 的原生 `EditText` 必须显式消费设置“字体大小”的同一全局倍率；已输入文字和“回复 南枫AI”占位文字同步按小／标准／大切换，标准档保持 `16sp`。字号切换只更新文字与其自然行高，不改变 Composer 外层、单行 `36dp` 编辑区、展开态上下限或底部 `60dp` 功能行几何。
- 附件加号为圆端、圆润笔画，视觉大小与命中面协调，不得过长、尖角或再套方形底。附件菜单文字与图标是纯黑色，保证清晰。相机／图片／文件之后提供“基础风格和语气”，一级行右侧直接显示当前普通会话最终选中的风格；点击进入同一浮层的二级列表，固定按默认、直言不讳、专业可靠、亲和友善、高效务实、风趣搞笑排列，只显示标题与选中勾号，不显示说明小字或完成按钮。“默认”是首个可选的中性风格。当前会话显式选择的优先级高于设置中的全局风格；没有当前会话覆盖时，直接继承设置里当前选定的风格。选择即时持久覆盖当前会话并关闭浮层，可在对话过程中反复切换，只影响后续回答，不修改设置总开关、其他会话或此前回答。菜单最底部固定提供与设置一致的主题色地球图标及“实时网页搜索”开关，不另用“当前对话联网”名称，也不显示重复小字；首次进入继承设置中的全局“实时网页搜索”值，切换后只持久覆盖当前普通会话、不中断草稿且不改全局默认或其他会话。它复用现有白色浮层、主题色与胶囊开关轮廓，不在 Composer 模型名下方增加常驻状态小字，也不新增 Composer 常驻按钮。模型选择的具体模型列表用当前会话的“实时联网”／“未联网”替代泛化的“官方实时联网检索”；服务商前缀照常保留，DeepSeek 继续先显示当前高峰／低谷。该小字只表达当前会话开关状态，不能冒充单条回答结果。
- Desktop 映射同一 Composer 语义时，加号面板与模型选择面必须共用短暂选择面的遮罩、点外关闭、子层返回和焦点恢复 owner，不得另建旧式 Popover 生命周期。宽屏允许把加号面板锚定 Composer 并保持约 `280px` 宽、`22px` 完整圆角，但相机／图片／文件／基础风格和语气／实时网页搜索的顺序、六风格单选与会话开关语义不得改变。Web 预览不具备私有附件能力时必须失败关闭；原生 Desktop 的实时网页搜索控件使用标准 switch 可访问语义并暴露 `aria-checked`。空白普通会话选择的风格／联网值必须在首条请求构建前与新会话原子落库；临时聊天不展示不能生效的普通会话偏好入口。
- Composer 与 Assistant 回复页脚统一显示短模型名。Claude 与 GPT 延续已确认的系列短名，例如 `Sonnet 5`、`Opus 5`、`Fable 5.1`、`Astra`、`5.6 Sol`、`5.6 Terra`；其他当前模型采用“品牌／系列 + 核心版本”，例如 `DS V4`、`GLM 5.3`、`Qwen 3.7`、`Gemini 3.8`、`Kimi K3`，不显示 Flash、Plus、Pro、Max 等速度／档位后缀。不得显示 Provider、路由或模型 ID。主界面底部 Composer 的短模型名由普通会话和临时聊天共用同一入口，保持既有 `13sp`、圆润字体、宽度与胶囊几何，并使用 `Bold`。Assistant 回复页脚、模型选择面、模型设置、调用／费用／上下文／诊断记录、知识溯源及其他模型名同样使用 `Bold`；模型选择根层的“自动／日常／深度”三个主标题以及进入子页后顶部的“日常／深度”标题都必须使用 `Bold`，其下方说明文字保持普通辅助层级。其中需要精确识别模型的页面继续显示目录中的完整具体模型名，不得被短名规则误覆盖。
- 主界面的模型选择小卡与侧栏会话长按菜单属于短暂选择面：其中的标题、选项与说明文字统一使用主界面同档字号的 `90%` 紧凑密度，仍完整跟随“小／标准／大”；不缩小菜单行高、图标、卡片或触控面。侧栏会话列标题单独使用 `14sp / 18sp` 基线，略大于其日期并按全局字号档位缩放。
- Assistant 回复页脚在短模型名之后显示该请求金额：OpenRouter 返回的 `usage.cost` 是权威原币值，合法的零金额必须保留；只在无法取得权威值时，当前目录中的每个模型按版本化本机价目表生成 token-only 估算，历史 token-only 记录也即时补算。估算不包含响应未披露的联网工具、优惠或缓存写入费用。所有面向用户的金额统一投影为人民币，美元按当前版本冻结的同日参考汇率换算；原始微单位、ISO 币种、价格版本及实际／估算来源仍保持不变。**主界面页脚仅显示 `¥` 金额本身：不显示“约”、`≈` 或“估算”，每笔人民币金额以 `HALF_UP` 四舍五入并固定显示四位小数；这不改写领域数据、费用与用量页、设置或任何估算标识。**时间、模型和金额放得下时保持一行；屏幕或字体缩放导致放不下时，金额必须另起一行靠右显示，禁止逐字符竖排、截断金额或挤压操作图标。费用汇总、币种换算、幂等和 fallback 的真实规则由费用合同定义。
- “费用与用量”的本机累计保持独立汇总卡；`会话、会话标题整理、历史资料整理、南枫转写` 四类摘要固定收进一张高明度 2×2 组合卡，以一条横分隔和一条纵分隔建立四个等宽语义区。每区不显示图标，只保留标题和两行统一信息：左侧“次数”、右侧调用次数；左侧“费用”、右侧以 `约 ¥…` 展示已知人民币总额。会话费用合并已知服务商实收与本地估算；来源、模型、Token 和实际／估算明细只在下方分段账本保留，摘要金额不重复显示“估算”。四类逐次明细仍由下方分段选择切换。
- 费用四格仅保持同行等高以连续分隔线，整体高度必须由标题和两行数据自然撑开，不做正方形、固定高度或最小高度约束。
- 每条普通 Assistant 回复的三点菜单固定提供总入口“本次回答信息”，替代“本次上下文来源”。轻量白色 Dialog 首先显示该回答生成时真正使用的“基础风格和语气”，再显示最终“实时网络”结果：只有 Provider 官方联网路由返回可验证 HTTP(S) 来源并形成该条完整回答时才写“已实际使用”，关闭开关或本次没有走联网路由写“本次未使用”；旧回答没有持久证据时诚实写“未记录（旧回答）”，不得按当前开关或当前风格倒推。若本次还实际发送了本地上下文，再在同一弹层列“本次上下文来源”；风格已在顶部显示，不在来源区重复。全程不显示正文、Prompt、附件、Provider 原始请求或凭据。该动作不在聊天主页或 Composer 新增常驻回答状态；弹层继承统一 `0.12f` 轻量遮罩。
- 临时聊天没有 Assistant 回复、Provider 调用或回答级上下文入口；进入时需明确说明它最多本机恢复 24 小时，并隔离记忆、资料库、普通搜索、自动标题与记忆摘要。临时聊天的“模型”仅为本次本机标识，不能显示为实际模型选择或调用。
- 用户在“个性化”明确启用并填写昵称后，新对话首个成功 Assistant 回复必须先以该昵称自然称呼用户；规则在 OpenRouter、千问、DeepSeek、自动路由与比较模式的共用正常聊天请求层生效。用户在当前消息明确要求别的称呼时，以当前要求为准；后续回复不强制重复称呼。流式回复只在完成并已取得独立思考内容后写入最终可见正文：若**思考文本的末尾不超过 16 个字符**被 Provider 重复到正文开头，且其后立刻是配置的昵称，才移除该重叠；除此之外不得猜测、裁剪或移动任何正常正文。
- 普通发送使用 `normal-chat-egress-v2`：界面用本地路由快照显示完整 Provider／模型名称，点击当下将该快照中的逻辑预设、实际 API 模型 ID 与正文／附件指纹一起授权。ViewModel 在保存前校验会话 ID 与草稿，前台服务完整传递快照；执行器不持有当前模型选择 owner，不在排队后重读选择或重算 Auto。目录刷新前后均校验 Provider／API 模型 ID，不匹配则在材料桥、secret 读取和正文网络调用前停止。发送期间禁用模型入口只是交互辅助，真正的门禁是授权快照。旧 v1 审计记录仍可读，但不能作为新发送授权。
- Auto 的配置、凭据 presence、能力与健康筛选在发送前的本地预览中完成；只读取元数据，不解密 secret，不刷新远端目录。界面与点击共用同一份快照；可用性在排队后改变时只允许原接收方成功或明确失败，不能暗换其他候选。流式刷新复用已有快照，终态重新读取本地可用性。
- 手动选择具体模型后必须持续使用该模型；`Auto` 才可自动路由。可见名、实际调用与记录归因不得互相伪造。
- `Auto` 只在发送前进行一次确定性选择，先判定任务路线，再按该路线的固定顺序筛选。普通文本顺序为 `DeepSeek V4.1 Flash → GPT-5.6 Terra → Claude Sonnet 5 → GLM-5.3 Flash → Qwen3.7-Plus → Gemini 3.8 Flash → Qwen3.6 Flash → GPT-5.6 Luna → Claude Haiku 4.5 → DeepSeek V4 Pro → GLM-5.3 → Qwen3.8-Max → GPT-5.6 Sol → Claude Opus 5 → Claude Fable 5.1 → GPT-6 Astra`；复杂推理顺序为 `GPT-6 Astra → GPT-5.6 Sol → DeepSeek V4 Pro → GLM-5.3 → Qwen3.8-Max → Claude Opus 5 → Claude Fable 5.1 → GPT-5.6 Terra → Claude Sonnet 5 → DeepSeek V4.1 Flash → Qwen3.7-Plus → GLM-5.3 Flash → Gemini 3.8 Flash → Qwen3.6 Flash → GPT-5.6 Luna → Claude Haiku 4.5`；有附件时优先进入附件路线，顺序为 `Qwen3.7-Plus → Qwen3.6 Flash → GPT-5.6 Terra → Claude Sonnet 5 → GPT-5.6 Sol → Claude Opus 5 → DeepSeek V4.1 Flash → GLM-5.3 Flash → DeepSeek V4 Pro → GLM-5.3 → Qwen3.8-Max → GPT-5.6 Luna → Claude Haiku 4.5 → Claude Fable 5.1 → GPT-6 Astra → Gemini 3.8 Flash`；`Gemini 3.8 Flash` 固定为该路线最后兜底。三条路线都必须覆盖全部当前聊天预设；历史 Fable 5 是只读归因路由，不能重新进入 Auto。附件路由应用统一解析层保证，不再因最终回答模型缺少原生多模态能力就屏蔽该模型。
- 普通文本只有在输入达到 `2400` 字符，或明确出现深度分析、完整方案、架构／重构／审计、根因／权衡、复杂调试、多步骤推理、投资／估值／风险传导等深度工作信号时，才进入复杂推理路线；普通“分析一下”不得自动升档。资料库的全局条目总数不属于任务复杂度，不能再触发升档。附件优先级高于复杂文本信号，避免复杂任务先选到不支持附件的模型。
- 每条路线只保留已启用、有凭据、可精确解析、支持文本且健康状态非 `UNAVAILABLE` 的最终回答候选，同一路线中 `DEGRADED` 必须排在健康／未知状态之后。安全文本与 `MD/TXT/JSON/CSV/XML/YAML/HTML`、`DOCX/XLSX/PPTX` 只在本机完整转为文本；PDF、图片、视频等材料只按当前选中模型已证明的原生协议发送。普通聊天不得为附件偷偷请求千问、智谱或任何其他中间模型，也不得替换最终模型；当前模型不支持的材料必须在发送前明确失败并保留原附件，不得只发封面、首页、缩略图或空材料。
- Composer 有附件时不显示冗长的外发／中转／计费小字；仅保留当前模型名称和必要的失败说明。附件解析或发送错误只能绑定当次失败的 `ConversationId`；切换、新建或打开其他对话后不得继续显示上一对话的错误。
- 所有输入框的选中背景、光标和拖拽手柄统一使用主题色（背景可用主题色透明度），不能残留系统青绿／固定橙色。

## 6. 模型选择面、短暂面板与消息动作

- 模型选择可作为与 Composer 直接相关的短暂选择面；点击遮罩关闭，子层先返回上层，再关闭根层。不得把它扩展为设置页的通用弹窗模式。
- 模型候选显示完整、稳定、可辨识的目录名称；完整弹层内容须可见且可滚动，不能以圆形小弹窗裁掉信息。
- 模型选择根层只保留“自动选择”以及“日常”“深度”两个手动分组；不再展示“对比”或“图像 / 视频 / PDF”分组，也不在具体候选目录保留其旧逻辑 ID。历史会话若仍保存旧 `logical:compare:*` 或 `logical:media:*`，读取时必须安全回退并显示为“自动”，不得继续发起双模型请求或错误标记旧项已选中。附件能力不在模型选择面阻断手动候选；模型目录仍保留真实的原生能力元数据，实际发送由统一解析层在本机转文本、原生直送或显式桥接之间决定，不伪造 Provider 原生支持。
- “深度”手动候选固定按 `Claude Fable 5.1 → Claude Opus 5 → GPT-6 Astra → DeepSeek V4 Pro → GPT-5.6 Sol → GLM-5.3 → Qwen3.8-Max` 展示。Fable 5.1、Opus 5、Astra 与 Sol 的 OpenRouter 实际请求统一显式传入 `reasoning.effort=high`；切换实时联网时只增加官方搜索工具，不能丢失 High。`GLM-5.3` 是独立于 `GLM-5.3 Flash` 的智谱官方直连聊天预设，API 模型 ID 固定为 `glm-5.3`，复用同一份智谱加密 API Key；当前智谱设置选择 Flash 时也不得阻断用户在会话中手动选择旗舰模型。该顺序只定义用户打开“深度”时的手动选择面，沿用各自既有 Provider、实际调用和费用归因链；不改变自动标题、历史资料整理、智谱默认 Flash 预设或已有会话的模型 override。
- `GLM-5.3` 每次请求必须显式发送 `thinking.type=enabled` 与 `reasoning_effort=max`，并沿用智谱 Chat Completions 的官方 `web_search` 工具、思考与正文流式解码、Token／耗时／失败诊断和精确模型归因。`MD/TXT/JSON/CSV/XML/YAML/HTML` 与 Office 文档先本机完整转文本；普通 PDF 优先本机文本层，扫描 PDF／图片可经 GLM-OCR，图片／视频等可经 Qwen3.7-Plus 转成 Markdown，再由 `GLM-5.3` 作最终回答。不得伪称智谱原生接收了未获协议证明的二进制格式，也不得因为桥接而把最终模型或调用记录改成桥接模型。
- “日常”候选固定按 `Claude Sonnet 5 → DeepSeek V4.1 Flash → GPT-5.6 Terra → GLM-5.3 Flash → Qwen3.7-Plus → Gemini 3.8 Flash` 展示；这里只定义用户手动选择面的顺序，不得反向推导 `Auto`、自动标题、历史资料整理、模型能力或当前会话 override 的顺序。`GLM-5.3 Flash` 通过智谱官方直连执行；用户手动选中时可用，会话标题或历史资料整理命中共享顺序的第二位时也可用。该预设的每次文本请求必须由智谱 Adapter 明确发送 `thinking.type=enabled` 与 `reasoning_effort=max`，不能依赖服务端默认档位，也不能把此参数泄漏给其他 Provider。它已按智谱 Chat Completions 的 `web_search` 工具接入官方实时检索；普通聊天中的文本／Office 附件以本机文本进入该 Adapter，图片、PDF 或视频先经统一解析层投影为 Markdown，不把未获官方协议证据的多模态 payload 伪造为智谱 GLM-5.3 原生输入。
- “日常”候选包含 `DeepSeek V4.1 Flash`，通过现有 DeepSeek 官方直连执行；它既可由用户手动选择，也是 `Auto` 普通文本、会话标题整理和历史资料整理的首选，但不改变 DeepSeek 的 V4 Pro Provider 默认预设或已有会话。完整名称用于选择面，Composer 与新消息页脚显示 `DS V4.1`；正式 API ID 为 `deepseek-flash`，图片可原生发送，PDF、视频和音频继续走既有解析边界，不宣称原生支持。内部 `DEEPSEEK_V4_FLASH` 保留为持久化兼容键，旧调用名称和归因不重写。
- “日常”的 `DeepSeek V4.1 Flash` 与“深度”的 `DeepSeek V4 Pro` 在模型名下方显示同一实时峰谷状态：`当前低谷`／`当前高峰`置于小字开头，仅该状态使用当前主题色与粗体；后接当前会话的“· 实时联网”或“· 未联网”，使用与其他模型一致的普通辅助文字颜色和常规字重，不跟随主题色。峰谷状态只由共享的 UTC 计费窗口 owner 计算：高峰为 UTC 周一至周五 `01:00–04:00`、`06:00–10:00 UTC`，即北京时间 `09:00–12:00`、`14:00–18:00`，周末及其余时段为低谷；边界采用左闭右开。选择面停留在分界点时必须自动刷新，不依赖重开页面、设备当前时区或手工写死文案。新版 Flash 本机 token-only 费用估算消费同一 owner 和调用发生时间；旧 ID 的历史价目仍按原版本保留，Provider 实际结算优先。升级证据、价格和平台差异见 [V4.1 升级记录](review/20260910/DEEPSEEK_V41_UPGRADE.md)。
- Assistant 页脚及复制、分享、分支等动作遵循紧凑、圆润、无黑边的图标语言。首个操作图形的视觉起点必须与上方 Assistant 正文左缘对齐，不因保留 `36dp` 点击面在前方留下空挡；点击面仍完整保留。Assistant 页脚第二个操作固定使用圆润分享图标与“分享”可访问名，实际将该条当前可见 Assistant 回复重建为 `.md` 后交给系统保存／分享；其三点菜单不得再出现重复的“导出 Markdown”，只保留“本次回答信息”和创建分支等非重复动作；其中“创建分支”固定使用正文色 `20dp` 的圆润 `CallSplit` 图标，不能只留下文字或弱化为不可见的装饰。会话操作弹窗同样只保留一条圆润分享图标与“分享”命名的入口，实际将该会话当前路径重建为 `.md`；禁止在其相邻位置再陈列“导出 Markdown”。两个范围均不导出 Prompt、Provider 原始回包、凭据、隐藏分支、其他会话或附件字节。文件名直接使用当前对话标题并加两位短序号（例如 `模型费用分析-03.md`），以区分多个分享文件；只清洗文件系统不允许的字符，禁止改用长时间戳或无识别度前缀。附件自身的“分享”仍传递未修改原文件，不受正文 Markdown 分享合并影响。
- 会话长按菜单中，“未读”紧跟在“置顶／取消置顶”下方，“收藏／取消收藏”随后。收藏与手动未读都是本机持久化的独立标记；收藏不改变日常排序，手动未读只按本节提升所属分组内优先级。归档或移入回收站时收藏仍按既有规则取消；手动未读在不可见范围不展示，恢复到活跃列表后继续兑现，直到真正点击打开。Desktop 关闭“自动未读提示”时，只隐藏自动提醒；用户手动标记仍必须立即显示当前主题色圆点，且仅在原生回读确认持久化后提示成功。
- 联网能力不与“深度档”绑定：所有档位、所有模型按当前 Provider 能力享有同样的联网开关／调用路径；普通发送优先采用当前会话的联网覆盖值，未覆盖时才继承设置全局值。无法联网时必须如实显示，不得默默降级或假称已联网。
- 完整回答与联网证据分开判定：服务商已完整返回正文时，缺少公开来源不能令回答失败、阻断保存或阻断自动标题。无来源的完成审计固定为 `WEB_SEARCH_COMPLETED_WITHOUT_SOURCES`；“已实际使用”只依据 Provider 搜索事件或合法公开来源，不从用户开关／正文链接猜测。显式 `length/max_tokens`、内容过滤、Responses incomplete/failed、空正文、网络未知和持久化失败仍保留真实失败态，不静默重发。旧失败审计不回写成成功。
- 千问 Responses 联网回复只显示官方 `response.output_text.delta` 增量；搜索状态、`<tool_use>`、`<tool_result>` 或任何原始工具载荷都不是 Assistant 正文。页面可持续呈现真实正文增量；只在 Provider 明确完成后进入完成态，半截输出、失败或超时仍原位显示未完成与重试入口。`Qwen3.8-Max` 的纯文本实时信息请求固定改走官方 Chat Completions 联网路线，显式发送 `enable_search=true` 与强制检索参数，整体生命期硬上限为 3 分钟；其他千问纯文本预设仍沿用 Responses，含附件请求继续走既有 Chat Completions 解析路线。`Qwen3.8-Max` 的 Chat Completions 与 Responses 两条请求都必须显式发送 `reasoning_effort=low`，不得继承服务端默认 `xhigh`；推理加正文的单次组合输出上限为 `16,384` Token。Provider 返回 `reasoning_tokens` 时，调用归因和费用页必须分别显示推理与正文 Token；历史记录未返回时只能显示“推理明细未返回”，禁止从总输出或金额伪造拆分。

## 7. 全屏搜索与本地预览

- 从会话菜单或滑出操作带打开“重命名”时，标题输入框必须在弹层出现后自动请求焦点、唤起系统键盘，并一次性全选当前标题；用户的后续输入只修改选区和文本，不得在每次字符变化时重置为全选。重命名弹层左对齐并精确铺满当前左侧栏宽度：窄屏为 `min(320dp, 可用宽度)`，展开内屏为可用宽度的 `2/3`。保存、取消、点外关闭与既有手动重命名 owner 不变。
- 搜索索引、时间、附件类型、安全预览、搜索历史和真实数据边界由 `P6F2_UNIFIED_SEARCH_HISTORY_AND_LOCAL_CONTENT_PREVIEW_CONTRACT.md` 负责；本合同覆盖其中所有 Android 搜索的视觉数值与皮肤表现。

## 8. 文字阅读与消息内容

- 单独成行的材料标签 `<图片>`、`<PDF>`、`<视频>`、`<音频>`、`<文件>` 一律采用同一标准加粗投影；不得依赖模型是否自行补写 Markdown 加粗而出现同类标签粗细不一致。标签文本、附件语义和模型原始回复均不改写。
- Provider 单独返回的思考／检索草稿必须与最终答复分成独立内容块，不得拼接进正文、复制文本、搜索索引、后续模型上下文、自动标题或可见导出。它只在该 Assistant 回复顶部显示为“思考过程”折叠面，默认收起；点击才展开完整原文。已保存的旧 DeepSeek 混合英文计划记录在“英文计划轨迹 + 明确中文结论开场”的高置信条件下也只在内存阅读层折叠，不回写历史原文。该面使用 `16dp` 圆角矩形与中性表面，严禁把多行内容做成胶囊，也不得为没有过程内容的回复制造占位。
- 普通聊天因服务未完成而显示“发送未完成”时，点击“重试”必须在同一交互帧关闭该失败面，不得等待网络回包；随后为原用户消息创建新的持久化 Assistant 占位节点，沿用该消息对应的图片／文档／文本初步回复模板，并固定显示“南枫AI 继续生成…”。首个真实流式片段到达后替换占位内容；再次失败或取消时如实终态并仅在可重试时重新提供失败面。重试仍沿用原请求幂等编号及原模型／服务商，不得默默改路由。
- 正文代码表面按平台区分：Android 保留灰色阅读背景上的亮色代码卡，浅色卡片为白色；Desktop 白色阅读背景上的代码块与行内代码统一采用低对比浅灰底（`#f7f8f8`）。深色代码卡仍为比阅读背景更亮的炭灰。双端代码卡均为无外框圆角表面；语言标签居左，“图标＋复制”按钮居右且图文整组居中，常态透明、不单独铺底色，直接透出代码卡背景；命中及反馈轮廓仍保持胶囊形，头部与代码之间仅一条细分隔线。常见语言的注释、字符串、键名、数字及关键字采用克制配色，未知语言保持原样。保留缩进、Unicode、引号、换行和原文复制；长行只在代码区横向滚动，头部不跟随；查找命中保留原始偏移，不把代码解析成正文富文本。代码卡不用胶囊形状，表格与行内代码沿用各自组件。
- 正文、标题、列表、表格、引用、代码、来源 chip 与附件仍按其语义呈现；模型近似 Markdown 的明确格式错误须在内存投影中归一化：行内标题井号转为独立标题、缺空格标题补齐、可识别的两／三反引号代码围栏转为代码块、紧贴文本的列表前缀转为列表。CSS 色值（如 `#fff`、`#FFFFFF`）和同类普通文本绝不得被“缺空格标题”修复误判为标题；转义的 `\#`、`\*`、反引号应按真实语义投影，未闭合或孤立的反引号、井号、列表星号与来源分隔符不直接呈现。来源只有有效 http(s) 链接时才显示入口，禁止“主要参考：、 、 、”等占位噪声。深色皮肤同步提供可读的正文／次要文字／分隔线，不得出现黑字、白卡或高饱和硬边。
- 本地安全文本预览中的 Markdown／近似 Markdown 复用同一安全阅读投影：不显示 `#`、`>`、`**`、列表前缀和代码围栏等控制字符，按标题、正文、引用、列表、强调、代码与表格语义排版；链接只显示文字，不可执行。预览使用克制的独立字号层级：正文 `15sp / 23sp`，三级标题 `19sp / 18sp / 17sp`，保留相对层次但不得复制 Assistant 页面级大标题跳变。浅色预览顶部使用纯白面延伸到状态栏并显示黑色系统图标；深色皮肤使用对应前景面与浅色图标。预览底部不再陈列长按复制、下载或分享的重复说明，也不展示 UTF-8、HTML、脚本等低价值实现说明；顶部复制、下载、分享操作保持可用。排版仅作用于内存阅读层，下载、分享和存储的原文件不改写。
- 用户气泡在浅、深皮肤中均比背景更易分辨，但保持低饱和主题派生色；不使用纯主题高饱和块，也不因长文本变成椭圆／圆形。
- 本地来源、上下文或联网资料不得通过空白卡、伪成功状态或无意义小字占位。必要状态要有用户可理解的事实；冗余解释性小字应删除。

## 9. 验收门

- 自动检查至少覆盖：主题切换下无硬编码橙色；浅色前景白／无黑边；暗色文本白／多层画布同色；冻结阴影参数及其接收控件；一键到底在 Composer 外层之后绘制；Composer 短名与其他精确名称分流；焦点多行编辑区的 `10dp / 28dp / 60dp` 分工与发送区隔离；选中颜色；滑出操作点外收起；侧栏末项可上移；归档／回收站创建时间及删除；搜索全皮肤覆盖。
- 生成连续性验收至少覆盖：A 会话生成时切到 B、进入设置／搜索再返回、应用短暂退到后台再返回、A 与 B 并行生成、停止 A 不影响 B、非当前会话完成后出现未读、进程终止后不自动重发。自动合同和构建只能证明 owner／投影规则，真实 Provider 与系统杀进程仍需独立授权验收。
- 视觉验收需覆盖浅色和深色的空对话、长对话、打开键盘、左侧栏、搜索五分类、已归档／回收站；构建或安装只能证明各自层级，不能替代真实观感与手势。

- 消息长按菜单的复制、选择文本、编辑消息、分享统一使用同一整行“图标＋文字”组件：固定图标列、文字左缘、行高和内边距；复制项禁止使用独立仅图标分支。菜单宽度收紧至 `200dp`、操作行高 `42dp`，文字 `14sp / 20sp / Normal` 标准字级、图标 `18dp`，图文间距 `12dp`；日期使用 `11sp` 辅助字级及 `24dp` 槽位，弹层定位与实际行高共用常量。成功复制后同一行显示勾选图标及“已复制”，反馈结束恢复“复制”，不能改变行宽或图文位置。

- Android 正文表格外框与内部横纵分隔线统一使用阅读画布 `ConversationWorkspaceCanvas` 的背景色，不使用独立高对比描边。

- 双端表格右上角复制按钮不单独铺底色、不画边框或阴影，直接透出表格底色，保留图标与命中面。Android 代码／表格横向滚动优先于侧栏；内部仍可向起点滚动时不得打开侧栏，只有到达最左端后的未消费右滑距离达到正常侧栏阈值，松手才打开。左滑、惯性滚动、程序滚动及多个不足阈值的独立手势不得触发侧栏。系统取消、失去触摸所有权或页面销毁不得当作松手打开；每次拖动开始与取消都清除边界余量，仅正常拖动释放可以完成交接。
