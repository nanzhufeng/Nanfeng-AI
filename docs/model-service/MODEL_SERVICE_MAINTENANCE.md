# 模型新增、升级与维护流程

先读[总架构](MODEL_SERVICE_ARCHITECTURE.md)和[当前矩阵](MODEL_SERVICE_MATRIX.md)。这里唯一维护变更配方，具体行为仍归相应领域合同。本流程不保证未经实际验证的新上游自动可用。

## 1. 先判断变更类型

| 类型 | 应改内容 | 必须保持 |
|---|---|---|
| 只改展示名／品牌／密度 | 命名／UI组件与读取投影 | API ID、历史名称快照、费用与接收方 |
| 新型号／新版本部署 | 新稳定preset＋精确Provider/API ID，明确新默认与选择位置 | 旧Attempt、旧归因、旧账本；不把新版本冒称旧模型 |
| 已验同组API别名 | 精确、有限、可追溯的规范化与身份兼容 | 同组Key／渠道／模型；不能建立动态失败fallback |
| 新请求参数／协议 | Adapter及对应解码／终态／预算 | 领域成功语义、system、原材料及取消 |
| 新Provider／凭据分组 | 独立配置身份、固定端点、私有凭据、错误映射、授权 | 其他Provider配置、账号数据和旧接收方披露 |
| 授权／材料范围版本 | 新发送校验＋历史读取兼容＋重开回归 | 旧版本原值；读取兼容不等于新授权 |
| 退役／下线 | 从新选择／Auto移除；保留历史识别与明确失败 | 历史消息、原始模型与冻结用量；不静默切Auto |

## 2. 接入记录

实际编码前在本次变更记录写：preset/logical ID、Provider＋API ID、平台／Key分组、默认与选择位置、CHAT或独立任务用途、离线与联网端点／协议、实际输入类型、推理／温度／输出参数、完成事件、来源形态、用量字段／币种、价格版本、接口依据、失败及取消规则。

能力／价格／型号来自外部时记核验日期和主来源；仓库声明、官方文档、服务实际返回与真实场景成功分开记录。尚未明确的能力不写成true；新接口不能靠一个“兼容OpenAI”标签免除请求与终态测试。

## 3. 修改入口与层级

1. 在 `protocol/model-service/model-service-v1.json` 更新providers/models/specialModels；已有共用规则不复制，新例外写exceptions并指向唯一领域合同。它只描述已同步实现的配置，不是开关新功能的运行时配置。
2. 按authorities定位生产owner：Android目录、profile或OpenRouter版本化registry；Mac Rust目录；必要的ESM呈现。新增枚举、退役值、默认、品牌、logical选择、Auto排序要同时核对。Auto独立于显示顺序，Qwen Flash一类Auto专用项不能漏掉。
3. 接口未变时复用现有Adapter；接口有差异时更新或新增适配器，保持Provider字段专属。连接测试用同一已实施接口及固定合成材料，不把hi成功当附件或联网成功。
4. 更新输入能力与预算：真实文件完整读取、图片／PDF／音视频接口支持、单／多／混合附件、本机转换、上下文与响应字节、搜索次数、推理输出和超时。不要从模型介绍自动打开所有媒体。
   - 同时运行按维护manifest枚举的Android准备／实际Executor、Mac Rust实际coordinator和ESM授权矩阵。种子目录故障不能退化为缺少现用模型的伪文字能力；验证图片＋本机PDF相邻、原生＋辅助混合、图片＋音视频双读取方、读取凭据／终态／原选身份。真实验收检查全部附件的不同标记，而非只看COMPLETED。
5. 核对发送授权、重试冻结、返回身份、来源证明、Call计量和后台收尾。涉及数据或授权版本，补旧库升级／重开与UNKNOWN不重发；单改请求参数不为了整理增加schema。
6. 更新共享fixture、两端行为测试和唯一领域合同；根据实际副作用选功能审阅项，不新增未经确认的常驻按钮。更新生成矩阵，再跑静态门与对应回归。
7. 真实服务矩阵从同一合法chat_selectable集合选择、发送和计数，排除退役／OCR；筛选包含未知／空／非聊天项时在Key读取和网络前拒绝，禁止零请求或缺项绿色。联网验收仍需逐项来源、原模型非空回答与真实计量。

### 最小新增模型记录

填写真实、已核验的值后加入models；下面仅是字段示例，不是可调用模型：

```json
{
  "presetId": "新稳定枚举身份",
  "providerId": "已实现或本次新建的配置身份",
  "modelId": "服务实际接受的精确API ID",
  "displayName": "明确型号与渠道的配置显示名",
  "selection": "与当前手动分组或Auto专用位置一致",
  "exceptionIds": []
}
```

已有协议的新模型无需增加模型名条件来复制共用逻辑；必要差异用对应Adapter参数策略及exceptions登记。维护目录、生产目录、动态registry/profile、选择入口、Auto、接口与价格／用量owner必须一致，静态门通过后仍须行为／构建及所需真实验收。维护目录中的数量不是上限；测试包含超出现用数量的新模型样例。

## 4. 固定命令

在仓库根目录执行：

```sh
python3 protocol/scripts/verify-model-service-contract.py --write-matrix
python3 protocol/scripts/verify-model-service-contract.py
python3 -m unittest discover -s protocol/tests -p 'test_model_service_contract.py'
```

生成之前先验证生产目录／规则引用一致；错误不写矩阵。CI运行只读检查与反例测试，不自动改目录、装包或探测付费服务。变更若只改文档／维护工具，不重打应用；业务语义变更选相应owner行为测试和平台编译，真实验收另记。

## 5. 必测行为

| 范围 | 通过条件 |
|---|---|
| 身份与选模 | 新旧目录、Auto／手选、不可用／退役、返回ID缺失／不一致、重开与历史归因正确 |
| 请求 | API ID／端点／字段／角色精确；system、语言、用户材料和续写上下文不丢；拒绝不支持的参数 |
| 文本与附件 | 短句、有长正文的单附件、多附件、混合格式；正文长尾、损坏PDF、Office／ZIP失败不空成功 |
| 联网 | 实际搜索、真实结构化来源、材料逐项相关；缺来源、空工具结果、粘连首项、嵌套MarkdownURL、错query、漏／重复ID均正确处理 |
| 终态 | 流式和非流式成功，输出上限、半包、EOF、超时、取消、断网和本地写入失败；终态后旧delta不复活任务 |
| 计量 | 缓存／推理／重复usage、未知币种／金额、主回答＋检索、失败后恢复、重复记账与金额精度 |
| 生命周期 | 前台无岛、后台默认简洁、终态消失、切页不中断；强杀后保留准确未知／断点，不自动重发 |
| 历史 | 旧模型ID／别名／授权版本／价格版本在升级、导入／同步、重试和重开中保真 |

新型号先用公开合成控制和真实选中接口，不用用户私人原件或同品牌另一渠道的成功来代替。没有跑过的场景写NOT RUN；只验证文本就只开放有证据的文本能力。

## 6. 交付与回滚

把本次模型／协议／能力差异写领域合同，长期取舍写decision-log，代码范围、测试命令、skip、构建、原生及服务结果写PROJECT_STATUS/CURRENT_HANDOFF；不要将测试数写成永久规则。

保留改动前源码／维护目录／协议快照。只按本次路径回退，不能清理整个脏工作区。正式安装和发布是后续明确授权动作；重开与保数据验证不能被签名或构建替代。

若维护门失败，先识别哪个声明或owner产生分叉，再修正对应输入。不要通过修改历史记录、隐藏失败、删门禁、宽松通配模型ID或自动换协议来让检查变绿。
