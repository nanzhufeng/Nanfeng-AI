# 可迁移开发经验

> 2026-10-30复核。依据[当前开发档案](南枫AI完整开发档案.md)、[本轮全量复盘](verification/2026-10-30-project-retrospective/REPORT.md)、[代码checkpoint](verification/2026-10-30-code-checkpoint/REPORT.md)及其源码／测试／Git记录。以下区分可复用方法、南枫AI专属选择和移植前必须重验的条件，不把本项目结果扩写为其他软件已具备的能力。

## 通用原则

| 原则 | 适用场景与操作 | 验证方法／禁止的误用 | 本项目依据 |
|---|---|---|---|
| 事实来源与当前运行身份分开 | 先核对工作树、commit、构建输入、产物hash、安装身份，再定位行为 | 同版本不等于同字节；已提交不等于已安装／发布 | [checkpoint](verification/2026-10-30-code-checkpoint/REPORT.md)、[产物身份](verification/2026-10-30-risk-boundary-audit/candidate.json) |
| 先建立入口到回读的完整增量 | UI→业务owner→外部边界→事务→重开→显示；各层只有相应事实所有者 | 不让页面维护第二套状态，不用按钮存在代表业务完成 | [开发Skill](../.agents/skills/nanfeng-ai-development/SKILL.md)、[Room仓库](../app/src/main/java/com/nanzhufeng/ai/data/local/RoomConversationRepository.kt) |
| 结果确定性必须穿过聚合 | batch、补检、回退分支和最终调用保留UNKNOWN／取消／已知失败区别 | 中途注入未知，断言后续外部调用为0、原检查点仍在；部分成功不能改写为Ready | [双端风险修复](verification/2026-10-30-risk-boundary-audit/REPORT.md) |
| 协议完成、内容事实、计量事实分别建模 | 外部服务部分响应、断流、尾部usage、关闭异常分别处理 | 已知金额可保留而状态仍失败；部分正文不升级完成，缺失金额不记零 | [C12](C12_MODEL_NETWORK_PARITY_CONTRACT.md)、[费用合同](AI_USAGE_COST_AND_BALANCE_LEDGER_CONTRACT.md) |
| 资源边界放在实际消耗层 | 流式协议按原始字节限制，包含注释、工具、思考与无换行长行；超时保留适用已知事实 | 在真实decoder边界放反例；只限制可见字符串不能限制传输／解析资源 | [Transport](../app/src/main/java/com/nanzhufeng/ai/ai/OfficialProviderChatTransport.kt)、[故障回归](../app/src/test/java/com/nanzhufeng/ai/ai/ProviderStreamInterruptionTest.kt) |
| 清理不能覆盖主要结果 | 资源关闭有单一owner；读取失败与清理失败分别保存／判定 | 协议已完成后close异常不抹终态；没有终态不能由close成功推断完成 | [Opus修复证据](verification/2026-10-30-opus-eof/REPORT.md) |
| 外部动作前持久化可恢复状态 | 持久Attempt、预算预留、上传offset或journal应在外部副作用前具备恢复依据 | 模拟中断重开；后续成功只能结算本笔，不清较早未知。不将本地预留宣称服务端硬额度 | [验收Ledger](../app/src/acceptanceSupport/java/com/nanzhufeng/ai/acceptance/PublicAcceptanceBudgetLedger.kt)、[行为测试](../app/src/test/java/com/nanzhufeng/ai/acceptance/PublicAcceptanceBudgetLedgerTest.kt) |
| 接收方与材料授权绑定 | 本地选择／预览与外发分开；网络前核对准确材料、实际模型和Provider | 不因失败静默换Key／渠道／模型；材料中的指令不成为执行授权 | [运行上下文](ANDROID_RUNTIME_CONTEXT_CURRENT_CONTRACT.md)、[C12](C12_MODEL_NETWORK_PARITY_CONTRACT.md) |
| 逐项证据比成功标签更重要 | 多文件、长报告或检索任务验证每项标记、来源、覆盖和原模型最终回答 | HTTP200、模型自述、正文URL或首个成功行不等于全任务完成 | [全主题修复](verification/2026-10-15-attachment-search-all-topics/REPORT.md)、[混合附件回执](verification/2026-10-21-real-attachment-roundtrip/REPORT.md) |
| 账本保事实，展示可聚合 | 用不可变物理调用记账，展示层按任务分组；价格／币种／来源按发生时点冻结 | 不为了展示合并原Call、回填旧估价或用另一模型费率补未知 | [费用合同](AI_USAGE_COST_AND_BALANCE_LEDGER_CONTRACT.md)、[Desktop账本](../desktop/src-tauri/src/chat_call_accounting_v1.rs) |
| 追加与修改仍需专门owner | 完成后的可选元数据用运行绑定、幂等、冲突检查和事务追加 | 不为一次补写放宽所有历史记录可变性；验证关闭重开而非只看内存 | [思考保存修复](verification/2026-10-15-other-model-network-review/REPORT.md) |
| 数据隔离与恢复按真实存储边界设计 | 账号／区域／工作区身份、资产引用、严格格式、暂存和提交一起检查 | 备份／迁移用隔离数据；禁止靠清空用户库消除迁移失败 | [C15](C15_WORKSPACE_KNOWLEDGE_PARITY_CONTRACT.md)、[P5D](P5D_LOCAL_BACKUP_RESTORE_DELIVERY_CONTRACT.md) |
| 安全描述沿最终载荷核对 | 分清认证、TLS、hash、服务端可读payload与密文；旧名称不证明当前信任模型 | 检查serializer→HTTP→SQL链路，不把base64／HTTPS写成E2EE | [direct SQL](../supabase/migrations/202609180007_p8_account_isolated_sync.sql)、[P7F](P7F_SELECTED_CONVERSATION_SYNC_CONTRACT.md) |
| 修复根因与验收样本分别报告 | 原失败反例定位首个分叉；另一个成功样本只证明它自身 | 不从499、EOF异常类或新短题成功猜测网络关闭发起方；不自动重发未知请求 | [排错Skill](../.agents/skills/nanfeng-ai-debugging/SKILL.md)、[Opus报告](verification/2026-10-30-opus-eof/REPORT.md) |
| 文档、结构、行为和交付分层 | 全文件清单／语法扫描、语义审查、测试、原生、服务、发布分别标范围 | 测试数不是覆盖率；unsupported语言记not-checked；旧绿色不能覆盖新红灯 | [复盘证据](verification/2026-10-30-project-retrospective/REPORT.md)、[测试Skill](../.agents/skills/nanfeng-ai-testing-delivery/SKILL.md) |
| 一条规则只有一处权威 | 当前行为归领域合同，状态归交接，原因归决策，方法归Skill，历史保留日期 | 更新档案正文的陈旧事实，不仅堆顶部免责声明；不改历史原件制造一致 | [合同治理](CONTRACT_GOVERNANCE_CURRENT.md)、[文档Skill](../.agents/skills/nanfeng-ai-document-sync/SKILL.md) |

这些原则适用于有持久状态、外部副作用或多入口的软件；不要求简单本地工具照搬本项目全部状态机、账本和验收成本。

## 该项目专属内容

| 内容 | 为什么是专属选择 | 可抽取的方法 |
|---|---|---|
| CHAT／WORK物理分库且WORK入口隐藏 | 本项目产品范围、区域隔离与历史数据决定；隐藏不删owner | 先确定目标软件数据区域／账号／人工引用边界，再选择物理或逻辑隔离。[C15](C15_WORKSPACE_KNOWLEDGE_PARITY_CONTRACT.md) |
| Android Compose／Room与Desktop ESM／Tauri／Rust | 框架和原生生命周期不同；两端独立数据库 | 共享版本化语义与fixture，各端用自己的持久化owner。[档案](南枫AI完整开发档案.md#4-架构与数据流) |
| 23聊天部署、独立OCR、精确RC／Luna及Provider例外 | 来自当前manifest、授权范围和已记录接口行为，不是整个品牌能力 | 维护精确部署＋接口＋场景；目录与真实服务验收分开。[模型架构](model-service/MODEL_SERVICE_ARCHITECTURE.md) |
| 原件识读后原选模型回答 | 部分模型输入能力与用户要求共同决定接收方和计费链 | 把读取、查询、最终分析及实际接收方分别建模；目标产品重做材料授权。[C12](C12_MODEL_NETWORK_PARITY_CONTRACT.md) |
| 物理Call账本与人民币展示 | 本项目Provider来源、币种、价格快照和本地展示规则决定 | 采用不可变计量事实和独立显示聚合，具体汇率／费率不照搬。[费用合同](AI_USAGE_COST_AND_BALANCE_LEDGER_CONTRACT.md) |
| direct同步与旧密文迁移 | 已确定服务端信任方案及兼容旧记录，不是通用隐私推荐 | 明确最终payload与账号隔离，迁移兼容和安全说明同步。[SQL](../supabase/migrations/202609180007_p8_account_isolated_sync.sql) |
| PublicAcceptanceBudgetPolicy／Ledger | 隔离收费验收工具，不是正式用户消费账本 | 复用网络前预检／落盘和未知保留方法，不能将工具默认值当产品预算策略。[维护流程](model-service/MODEL_SERVICE_MAINTENANCE.md) |
| 主设备禁测、原签名覆盖和预览规范 | 用户长期设备规则与本项目交付身份；不是可迁移的安装授权 | 别的项目重新明确设备、签名、数据保护和真实验收条件。[AGENTS](../AGENTS.md)、[发布策略](GITHUB_REPOSITORY_AND_RELEASE_POLICY.md) |

## 不可直接照搬的部分

- **模型／接口／价格**：API ID、provider、Key组、工具参数、SSE终态、408／504映射、输出限制和费率依赖精确部署。移植前依据目标接口与真实回执核验；本轮复盘没有联网更新第三方规格。[模型维护流程](model-service/MODEL_SERVICE_MAINTENANCE.md)。
- **预算数字和成本保证**：本地预留是保守约束的一部分，不限制上游实际收费；历史已授权额度不能迁移为另一任务的授权。未知、超额及停止条件必须按目标环境设计。[风险报告](verification/2026-10-30-risk-boundary-audit/REPORT.md)。
- **信任与加密模型**：本项目direct同步不是E2EE。其他软件的密钥、监管、数据驻留和服务器可见性需独立决定；不能沿用旧encrypted命名做安全承诺。[P7F](P7F_SELECTED_CONVERSATION_SYNC_CONTRACT.md)。
- **数据schema／解析阈值**：Room72、Desktop主库45、检查点版本、中文事实分割、batch大小／TTL等是当前实现事实，不是推荐数值。新材料、语言、生命周期和升级路径需要新反例。[当前档案](南枫AI完整开发档案.md#3-技术栈配置与目录)。
- **历史成功与失败**：过去的22模型、混合媒体、旧Provider错误及产品1.0.32不构成新平台或新候选的验收；成功也不能倒推旧断流责任。[22模型矩阵](verification/2026-10-30-other-model-stream-audit/all22-matrix.json)。
- **设备／身份／发布**：bundle ID、appId、证书、账号、私有路径、安装授权和截图不能复制；签名相同不证明数据迁移成功，上传中不等于公开下载可用。[发布策略](GITHUB_REPOSITORY_AND_RELEASE_POLICY.md)。
- **UI与产品范围**：隐藏WORK、设置入口、皮肤和外屏简称是产品约束，不是其他软件默认交互。移植前确认目标平台输入、可访问性和用户需求。[Android设置](ANDROID_SETTINGS_UI_CURRENT_CONTRACT.md)、[C16](C16_THEME_FONT_OVERLAY_PARITY_CONTRACT.md)。
- **覆盖数字和工具能力**：文件数、语法通过数、测试总数不是审计深度。全量结构工具不检查Kotlin／Rust／SQL运行语义；另选目标语言工具，保留未检查项。[复盘结构结果](verification/2026-10-30-project-retrospective/structure.json)。

## 迁移到其他项目的步骤

1. 列入口、持久owner、外部接收方、失败确定性与用户授权，判断哪些专属假设不成立。
2. 选择一个可观察的垂直流程，建立目标材料与失败反例，定义成功、未知、计量和重开判据。
3. 用目标平台真实owner消费合成fixture；需要真实服务时只补未证明的边界，先明确费用与停止条件。
4. 分开保存源码、构建、原生、服务及发布证据；整理长期AGENTS、独立Skill和唯一领域合同，当前状态不写入永久规则。

新增方法只有在代码／行为证据支持时才继续沉淀；未验证推断留在项目待办，不升级为跨项目硬规则。
