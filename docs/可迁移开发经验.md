## 通用原则

| 原则 | 可复用做法 | 证据 |
| --- | --- | --- |
| 先分层再宣称完成 | 分开报告源码、单测、构建、隔离原生、主设备、真实服务；任一层的绿灯不能替代另一层 | [测试交付流程](../.agents/skills/nanfeng-ai-testing-delivery/SKILL.md)、[开发档案测试节](南枫AI完整开发档案.md#8-测试验证与交付方式) |
| 业务状态必须有唯一 owner | UI 只投影状态；持久化、后台、外部调用和 UI 回读经同一 owner 链路，避免两份业务真相 | Android `AppContainer.kt`、Desktop `lib.rs`、[开发流程](../.agents/skills/nanfeng-ai-development/SKILL.md) |
| 不确定外部结果不能当成功 | 为外部动作保留 Attempt、receipt、版本和 UNKNOWN；先核对，再决定是否重试 | `desktop_ordinary_chat_v1.rs`、[排错流程](../.agents/skills/nanfeng-ai-debugging/SKILL.md) |
| 数据迁移是产品行为 | 结构变化有连续前向迁移；运行中替换用 staging、原子切换、失败回滚和关闭重开验证 | `NanfengAiDatabase.kt`、`desktop_local_backup_v1.rs`、[P5-D](P5D_LOCAL_BACKUP_RESTORE_DELIVERY_CONTRACT.md) |
| 格式边界必须 fail closed | 导入、备份、协议与服务输入校验版本、来源、hash、路径、大小和冲突；未知字段或身份不猜测 | `protocol/scripts/`、`P7FManualConversationSync.kt`、[代码审查流程](../.agents/skills/nanfeng-ai-code-review/SKILL.md) |
| 测试应卡在公共行为边界 | 覆盖持久化、重开、并发、取消、迟到回读和失败分支；模拟 transport 与真实服务明确分层 | Android JVM、Node、Rust 与 protocol golden 的当前回归记录 |
| 文档也要有唯一职责 | 当前行为写合同，动态事实写交接，长期取舍写决策；档案只汇总证据并记录冲突 | [文档同步流程](../.agents/skills/nanfeng-ai-document-sync/SKILL.md) |

## 不可直接照搬的部分

- **安全模型**：不能因为本项目当前 direct 同步允许服务端读取正文，就降低其他产品的端到端加密、密钥轮换或合规要求。同步格式必须从目标威胁模型重新设计。
- **版本、Schema、模型和价格**：Room Schema 69、桌面迁移版本、Provider ID、超时、价格和 SDK 版本都是当前仓库事实，不是通用建议。
- **设备门禁**：OPPO 主设备的保数据覆盖限制适用于该用户环境；其他团队仍需制定自己的签名、测试设备、备份和发布策略，不能以“同签名”代替数据安全验证。
- **UI 细节**：胶囊、颜色、灰度、代码块、菜单密度和中英文文案来自南枫 AI 当前产品合同；仅在目标产品的用户研究、平台规范和视觉系统允许时复用。
- **测试数量**：1,235/447/301 是本次快照的执行结果，不是质量阈值。新项目应按风险和公共行为边界定义测试集合。

## 迁移到新项目的最小步骤

1. 先建立目标项目的入口、数据 owner、外部动作和证据层清单；不要复制实现文件。
2. 为每个持久化／网络边界定义输入、授权、幂等、失败与回读，并写一项可复现红灯。
3. 先用本地测试和隔离数据证明语义，再取得真实服务或设备授权；发布前重新核对签名、版本和远端附件。
4. 建立短 AGENTS、领域 Skill、现行合同、交接和档案的单一职责，不把一次性截图或临时版本号写成永久规则。

这些经验来自代码和验证路径，而非“任何技术栈都适用”的承诺；替换平台、数据类型、服务商或威胁模型时必须重新审计。
