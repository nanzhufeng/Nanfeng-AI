# 可迁移开发经验

> 归档依据：2026-08-31 对 HEAD `09f519f` 完成的复盘；代码冻结点 `b7e1c2f`、138 个 Git 提交、Room Schema 63、现行合同、完整源码／测试／配置结构扫描。后续 checkpoint 已执行 `1042 tests / 0 failures / 3 skipped`、`lintVitalRelease`、`assembleRelease` 与 APK 验签；旧计划、历史设备快照、未执行真实服务和 Desktop spike 不泛化为已完成事实。

## 2026-09-10 增量经验

- **恢复上下文应保存身份，不依赖列表排序。** 保存退出时的实际对象 ID 和有效时间，在恢复时检查对象可用性；旧格式缺少 ID 时使用明确默认入口。
- **快速设置保存必须只合并本次变更。** 串行提交当前 revision 的字段 patch；覆盖连续修改、关闭重开及失败保稿，独立设置 owner 分开验收。
- **全文替换需要事务和并发前置条件。** 新摘要与旧活动摘要状态同时提交；编辑期间修订变化应拒绝陈旧保存，避免静默覆盖新内容。
- **视觉回归应消费生产渲染器。** 用真实 HTML 与完整 CSS 验证最终颜色和背景覆盖，避免复制内联样式或字符串截取造成测试与产品分叉；computed style 不替代原生实看。
- **增量固化保留证据层级。** 把长交接无损归档，当前入口保留代码点、回归结果和未验项；历史成功只证明历史版本，已安装不能等同业务验收。

## 2026-09-01 checkpoint 增量（历史）

- **把默认值、会话覆盖和历史事实分开。** 设置里用户当前选定的风格是无会话覆盖时的默认；会话层保存“有覆盖／无覆盖”，不能把未知覆盖强制写成中性默认。每条回答再冻结生成时实际风格，之后切换设置或会话覆盖不得改写历史。
- **外部能力必须记录执行结果，不记录意图替身。** 联网开关和模型列表小字只表达当前意图；只有官方联网路由返回可验证来源并形成完整回答，回答级事实才可写“已实际使用”。此原则可迁移到工具调用、支付、同步、邮件和 Agent 动作。
- **短名称只属于展示层。** Composer 空间有限时可以用“品牌／系列 + 核心版本”提升识别度，但路由必须继续使用稳定逻辑 ID／真实模型 ID，设置、账本和历史归因保留完整名称；不能让短名参与 Provider 判断。
- **大型工作树分两层 checkpoint。** 先在完整回归后提交源码、测试、schema 和依赖，再用独立文档提交固化合同、交接、决策和档案；构建物、测试报告和临时截图不入库。这样既能回退代码，又能单独审阅文档裁决。
- **当时证据：** 代码 checkpoint `242ed1e`；Android `1082 / 0 failures / 0 errors / 3 skipped`，Desktop Node `141/141`、Rust `165/165`，Go 网关强制非缓存测试通过。OPPO 同签名覆盖读回字节一致且数据 inode 未变化；真实 Provider／远端服务仍未复验。

## 2026-08-31 checkpoint 增量（历史）

- **退役不是删除历史。** 一个模型从选择面退出时，保留稳定 ID 服务于历史归因，但将发送、重试和凭据读取之前的边界统一失败关闭；不能静默代选，避免用户以为仍在使用原模型。
- **媒体预览与原图查看是两层合同。** 卡片缩略图应复用已发送对话的本地投影，原图查看则以图片与视口的实际几何关系决定最小缩放和平移边界。不要用“先放大才能拖动”或固定初始位置替代内容边界。


## 一、通用原则

### 1. 让当前事实只有一个短入口

把视觉、设置、运行时等高频变化领域各自收敛为一份当前合同，历史设计、阶段计划和证据只保留发生时的价值。冲突时使用源码和可复现测试裁决，再写回当前入口。

- 依据：三份 Android 当前合同、`CURRENT_HANDOFF.md` 顶部读取门，以及旧 Schema／测试结论漂移。
- 可迁移：多阶段产品应分离当前规范与历史证据，避免多篇文档同时声称当前。

### 2. 用持久化事实而不是 UI 推断外部动作

外部请求应有可恢复状态、稳定标识、实际接收方和去敏错误码。结果未知时提示用户决定重试或放弃；不要因进程重启、界面关闭或模型切换而默默重发、换服务商或删除已提交内容。

- 依据：`NormalChatSendAttempt`、运行时事件、助手模型归因和普通聊天前台服务。
- 可迁移：支付、邮件、同步、上传、Agent 工具调用同样需要 attempt／receipt／unknown outcome，而不只是 loading 动画。

### 3. 把安全边界放在 owner，而非提示文案

凭据、附件、导入、恢复与 Provider egress 要有独立 domain／data owner，在写入或外发前执行范围、MIME、大小、schema、来源和原子性验证。UI 的“已确认”或“已保存”不能取代底层检查。

- 依据：私有附件仓、Keystore credential store、严格 JSON/ZIP/v2 restore owner、`LocalContextBroker`。
- 可迁移：本地数据产品应将文件选择器、URL、路径、token、未知字段与敏感正文拒绝在边界处。

### 4. 验证分层且不夸大

定向契约、编译／构建、全量单测、视觉、真机、真实服务分别证明不同事情。报告中必须同时给出通过面、失败面、设备／账号是否参与和剩余风险。

- 依据：当前 checkpoint Android 完整 JVM 为 `1042 / 0 failures / 3 skipped`，Release Lint／构建通过；未在本 checkpoint 安装或操作设备。历史真实 ZIP、Desktop Node／Rust、协议 golden 和 OPPO 覆盖仍各自保留在独立证据层。
- 可迁移：不能把可构建写成体验完成，也不能用一组定向通过掩盖全量失败。

### 5. 让设计令牌和手势规则集中复用

被频繁反馈的控件尺寸、弹层遮罩、滑出操作、自动滚动和阅读步进应有共享 owner 与契约，避免多入口各用比例计算或相似但不一致的手势。

- 依据：共享开关几何、轻量 Dialog scrim、阅读控制和操作带收起规则。
- 可迁移：跨页面组件应复用语义、命中面、形状、按压反馈和无障碍，而不仅是颜色。

### 6. 长任务不能绑定页面生命周期

耗时数分钟的导入、恢复、索引或迁移不能由 ViewModel 的一次 `show/list` 协程拥有。应把任务状态、进度、幂等键、失败类型和 checkpoint 持久化，再由受约束的后台调度 owner 续跑；页面只观察状态和发出重试／取消意图。

- 依据：`c1c9ae0` 在 Schema 56 引入 `AndroidP6KZipAssetRecoveryScheduler` 与内容无关 job；该任务和迁移在当前 Schema 63 仍保留，Room owner 按会话 checkpoint 续跑。
- 可迁移：媒体处理、离线同步、备份恢复、批量 OCR 和大包导入都应遵守“后台 owner + 持久化 checkpoint + UI 投影”。

### 7. 将“对象身份”和“出现位置”分开建模

同一附件字节可以在多条消息中出现：字节／catalog 用稳定 file ID 去重，消息中的每次引用单独保存 occurrence。若把“一个 file ID 只能属于一条消息”当成约束，会丢失合法引用；反过来若每次引用都复制字节，又会浪费空间并破坏一致性。

- 依据：ChatGPT ZIP 的共享 file ID、多消息引用、`P6KChatGptZipAssetMapper` 与 Room 映射 owner。
- 可迁移：邮件附件、相册素材、知识片段、云盘文件和跨文档引用都应区分 asset identity 与 occurrence identity。

### 8. 对树结构使用结构事实，而不是渲染顺序猜叶节点

parser 最后保留的可渲染节点可能仍有不可渲染后代，不能直接当作 branch leaf。应沿 source tree 选择合法后代叶，并把无法提交的会话显式计为失败；禁止用空结果吞异常。

- 依据：ChatGPT ZIP 最后一个附件的 `当前分支必须指向叶消息` 根因、合法后代叶修复与 `failedConversationCount`。
- 可迁移：评论树、版本树、工作流 DAG、邮件线程和事件溯源都应将结构身份与 UI 投影分离。

### 9. Opt-in 真实数据测试必须验证“确实执行”

测试任务成功不代表用户数据验收已运行。需要在 XML 中确认 `skipped=0`、输入来源是显式环境变量、输出不泄露正文，并把普通全量中的合法 skip 与单独实包门分开报告。

- 依据：Android 全量中的 3 个 ChatGPT ZIP opt-in skip，以及旧包／新包单独运行到 `skipped=0, failures=0` 的记录。
- 可迁移：大数据、外部服务、硬件和私有 fixture 的验收都应使用同样的“运行证明”。

### 10. 用材料桥接解决能力差异，不伪造模型原生支持

当用户选定的最终模型不原生理解 PDF、图片、视频或 Office 文件时，先由应用的可审计解析 owner 在本机取文本，必要时调用独立 OCR／材料模型生成忠实投影，再交给原选模型回答。最终模型、材料接收方、费用和失败必须分别归因；桥接不可用时停在外发前，不发空材料，不静默换最终模型。

- 依据：`UniversalChatAttachmentBridge`、本机 UTF-8／Office Open XML／PDF 文本层、GLM-OCR 与 Qwen 材料投影的分开账本。
- 可迁移：多模型产品应把“最终推理能力”和“输入材料标准化”解耦，而不在 capability 表中把所有模型标成全能。

### 11. 存储概览只统计活动 owner 的当前物理字节

导入 receipt、provenance 或历史 byteCount 只能证明“曾经发生”，不能证明某文件仍应计入图片／视频／文档占用。实时概览应对活动 owner 去重，读当前受管文件长度；无 owner 但仍在磁盘的文件单列为残留并计入总量，只经显式清理入口删除。删除会话或来源时只有最后真实引用消失才能清理共享字节。

- 依据：`PrivateAttachmentAssetDao.referenceCount`、`AndroidPrivacyDataManager`、南枫转写 owner 和 ZIP 活动任务引用口径。
- 可迁移：媒体库、邮件附件、云盘缓存和导入系统都应把活动引用、历史证据和物理残留分层，不能用一个旧累计字段冒充实时占用。

### 12. 最终回归先冻结代码，再区分过期合同与真实回归

大型工作树收口时，先建立可回滚的本地 checkpoint，再运行全量测试。失败项不按“改到绿”处理，而是分为：已记录未完成基线、因当前产品决策而过期的静态合同、真实代码回归、环境／fixture 问题。只有第二类改合同，第三类改代码；已完成部分不重做，已有失败不冒充新回归。

- 依据：当前 checkpoint 的第一次 `1013 / 12 / 3` 与合同更新后 `1013 / 4 / 3`；8 项定向更新全通过，保留失败集与冻结前基线一致。
- 可迁移：长期项目的“最终回归”应交付失败集的稳定性和分类证据，而不只交付一个 Gradle 成功／失败状态。

### 13. 完整复盘先做全仓结构清单，再深读高风险 owner

“检查全部代码”不等于把所有源码一次性灌进上下文。先对跟踪文件、目录、扩展名、行数、实体、迁移、测试、危险 API 和完整提交主题做结构化扫描，再按入口、组合根、数据库、外发、文件、搜索和恢复链深读；最终档案要公开检查方法和未覆盖层。

- 依据：本轮先盘点 1084 个跟踪文件、296 个 Android 主 Kotlin 文件、258 个 JVM 测试目录文件（255 个 Kotlin）和 63 份 schema，再对 Activity、`AppContainer`、数据库、发送器、附件桥和当前合同收窄核对。
- 可迁移：大型仓库复盘应同时做到“覆盖完整”和“读取有界”，并避免把结构扫描误写成逐行人工审阅。

### 14. 巨型入口文件是可验证性的债务，不只是代码风格问题

当单个 Compose surface、ViewModel、数据库声明或组合根承担过多 owner 接线时，每次局部改动都会扩大静态合同、编译和视觉回归面。拆分应按状态／owner 边界进行，并先固定行为合同与性能基线；不能以删功能、隐藏内容或改布局伪造优化。

- 依据：当前 `ConversationWorkspace.kt` 10,842 行，`NanfengAiApp.kt` 3,596 行，数据库与 Foundation ViewModel 也超过 2,000 行。
- 可迁移：文件体量不是自动 bug，但当改动影响面、测试定位和审查成本持续增大时，应纳入路线而不是等待一次大重写。

## 二、该项目专属内容

### 1. Android 主设备交付边界

OPPO Find N5 保存用户数据：永久禁止 `connected*AndroidTest`，不得卸载、清数据、注入数据库或安装 Debug／仪器包；仅在明确授权、验签通过时用正式同签名包保数据覆盖，并读回包级身份。

这是本项目的设备风险模型，不应机械用于没有用户数据的隔离模拟器。

### 2. 当前普通聊天上下文语义

个性化资料、Memory、资料库与当前对话历史由 `LocalContextBroker` 在本机按开关、scope 和 token 预算选取。其开关和外发语义以运行时上下文合同为准。

这是南枫 AI 的产品授权设计；其他产品要根据数据分类、隐私许可和检索能力重新定义。

### 3. 多 Provider 与附件中转

本项目同时维护 OpenRouter 目录、Qwen／DeepSeek 档案、实际 Provider attribution 和可选 Go 附件中转网关。模型显示名、Provider、实际 model ID、能力和传输协议不是一回事。

只有确有多 Provider 和受控附件 egress 时才引入同等分层。

### 4. Room 连续迁移与严格工作区交换

当前 Schema 63、1→63 连续前向迁移和 v2 工作区交换强调保真、provenance、receipt、可续跑 checkpoint、空本机恢复与 fail-closed，适用于承载用户长期数据的个人工作台。

小型、无长期数据的应用不必复制如此多协议层，但必须保留与数据风险匹配的升级和回滚策略。

### 5. 南枫 AI 的模型接入必须是完整产品流程

本项目新增模型不只增加名称：还要进入 Provider 设置与凭据、Direct／Compare／Auto、能力表、附件桥、上下文／输出预算、实际归因、Token／费用、错误、调用记录、合同和回归。文件格式支持通过统一材料层补齐，不把所有模型原生能力伪设为 true。

这是南枫 AI 当前的多 Provider 产品合同；单一模型、无附件或无费用展示的产品不需要照搬全部层级，但仍应保留实际接收方与失败边界。

## 四、复用时的最小检查表

1. 明确代码、当前合同、历史证据的优先级并放进项目 `AGENTS.md`。
2. 为外部动作设计 attempt／receipt／unknown outcome，明确实际接收方和重试边界。
3. 把 Key、文件、导入、恢复和 egress 放进可测试 owner；审计去敏且不保存正文。
4. 先跑定向门，再跑全量门；opt-in 测试单独确认 `skipped=0`；完整报告失败数量及类别。
5. 真机、账号、付款或生产数据参与前，先核对授权、签名、回滚和数据保留路径。
6. 只有重复流程才沉淀为 `.agents/skills/`；当前状态留在档案与交接。
7. 新模型逐项核对目录、凭据、路由、材料桥、预算、归因、费用、错误、设置、测试和文档，不接受“能发请求”作为完整接入。
8. 复盘先输出结构清单与证据矩阵，再深读高风险 owner；明确哪些层未运行或只能沿用历史证据。
