# 可迁移开发经验

> 来源：2026-09-10 对南枫 AI `ef76fc4` 的复盘。每项经验由当前代码、测试或 Git 记录支持；它们不是所有软件必须照搬的模板。项目实现与现状见 [完整开发档案](南枫AI完整开发档案.md)，动态验证见 [当前交接](CURRENT_HANDOFF.md)。

## 一、通用原则

### 1. 用身份和持久状态恢复工作，不依赖页面排序

恢复的对象应有稳定 ID、有效状态及时间语义。置顶、搜索排序、列表首项不代表用户最后操作对象。南枫 AI 的启动恢复修复以退出 ID 取代排序回退，并检查空会话是否真的可复用。适用于编辑器、阅读器、财务工作台和多任务应用；时间窗属于具体产品决定。

依据：[启动策略](../app/src/main/java/com/nanzhufeng/ai/domain/ConversationAppEntryPolicy.kt)、[策略测试](../app/src/test/java/com/nanzhufeng/ai/domain/ConversationAppEntryPolicyTest.kt)、`c4aad94`。

### 2. UI 状态不能代替外部动作事实

发起、接收、完成、失败、取消和结果未知应有持久 Attempt／receipt；重试检查幂等和实际接收方。UNKNOWN 不应被“转圈结束”或进程重启解释为没执行。可迁移到上传、支付、任务代理和同步；是否允许自动重试取决于外部服务的可验证幂等能力。

依据：[发送 Attempt](../app/src/main/java/com/nanzhufeng/ai/domain/NormalChatSendAttempt.kt)、[runtime](../app/src/main/java/com/nanzhufeng/ai/domain/ConversationRuntime.kt)、[v2 原子恢复](../app/src/main/java/com/nanzhufeng/ai/domain/WorkspaceExchangeV2AtomicRestore.kt)。

### 3. 把业务内容与审计元数据分开

业务库可以按产品授权保存正文和附件；审计只保留判断动作所需的安全事实，不复制 Prompt、密钥或中间材料。不能把“日志禁止正文”扩成“业务也不能保存内容”，也不能因为需要排错就记录完整请求。

依据：[Room 模型](../app/src/main/java/com/nanzhufeng/ai/data/local/NanfengAiDatabase.kt)、[材料桥独立计账](../app/src/main/java/com/nanzhufeng/ai/ai/UniversalChatAttachmentBridge.kt)、[Usage](../desktop/src-tauri/src/usage_ledger_v1.rs)。

### 4. 保存本次变化，避免旧快照覆盖新状态

快速连续设置用字段 patch 和明确写入顺序；需要竞争控制时读最新 revision。整篇替换则校验编辑起点版本，在一个事务中保存新内容与旧版本状态。失败保留草稿。可用于设置、表单、文档编辑；跨进程／云端并发还需独立冲突协议，单队列不等于分布式锁。

依据：[设置保存回归](../desktop/tests/settings-save-serialization.test.mjs)、[设置 owner](../desktop/src-tauri/src/desktop_app_settings_v1.rs)、[摘要替换](../app/src/main/java/com/nanzhufeng/ai/data/local/RoomMemoryRepository.kt)。

### 5. 一份字节可以有多次引用

内容身份、引用 occurrence、来源和业务所有权分离。导入次数或历史 receipt 数不等于现存文件数；存储统计读当前物理字节，最后活动引用消失才删除。适用于知识库、媒体库和消息应用；不应只复制本项目的表结构而忽略新 owner。

依据：[私有附件 store](../app/src/main/java/com/nanzhufeng/ai/data/AndroidPrivateAttachmentStore.kt)、[P6-K 身份账本](../app/src/main/java/com/nanzhufeng/ai/data/local/RoomP6KImportIdentityLedger.kt)、[存储决策](decision-log.md)、`2fec04c`。

### 6. 跨端传递语义，避免共享内部数据库

显式版本、字段保真、资产清单、hash、严格预检、事务及重放回执，比“另一端直接读数据库”更能保留演进空间。未知字段或歧义来源不能默默丢失。成本是维护协议和迁移测试；简单一次性导出未必需要完整工作区 IR。

依据：[v2 reader](../app/src/main/java/com/nanzhufeng/ai/domain/NfaiExchangeV2PackageReader.kt)、[Desktop v2](../desktop/src-tauri/src/p6_workspace_exchange_v2.rs)、[ADR](ADR-002-P6A_DESKTOP_AND_EXCHANGE.md)、`2e997ae`／`34c4ab2`。

### 7. 能力、配置、请求意图和执行结果分层

模型目录支持某格式、凭据已存、用户打开联网、Provider 真正使用工具，是不同事实。应用材料解析也不等于模型原生多模态。历史答案应冻结实际归因，不能随当前设置重算；估算费用不能显示成实扣。这一方法可迁移到授权、通知、云备份和第三方 API。

依据：[模型解析](../app/src/main/java/com/nanzhufeng/ai/domain/ResolvedModel.kt)、[答案归因](../app/src/main/java/com/nanzhufeng/ai/domain/AssistantResponseModelAttribution.kt)、[费用估算](../app/src/main/java/com/nanzhufeng/ai/domain/ConversationCostEstimator.kt)。

### 8. 长任务应能跨页面和进程续跑

任务状态、输入引用、取消和 checkpoint 由持久 owner 持有，UI 只是投影。重新打开页面不应产生第二次请求；失败必须留下可恢复事实。可用于导入、转码和批处理，但不代表所有任务都适合自动重放。

依据：[ZIP 恢复调度](../app/src/main/java/com/nanzhufeng/ai/data/P6KZipAssetRecoveryScheduling.kt)、[普通聊天后台](../app/src/main/java/com/nanzhufeng/ai/background/NormalChatBackgroundExecution.kt)、`c1c9ae0`／`c34756a`。

### 9. 测试消费生产边界，证据层级不互换

尽量用实际 parser、renderer、持久化 owner 验证行为，避免复制实现后测自己的副本。主题色检查从旧 CSS 字符串切片改为生产 HTML＋完整 CSS 的 computed style，消除了假红灯。浏览器样式、原生窗口、实际系统选择器、用户升级和真实服务仍需各自证据。

依据：[主题检查](../desktop/scripts/check-theme-color-computed-style.mjs)、[Settings 回归](../desktop/tests/settings-save-serialization.test.mjs)、`c4aad94`。未执行的真实 ZIP 用例以 skip 保留，不能统计成成功。

### 10. 环境失败应先分类，不改产品来适配错误工具

Robolectric 缺 FTS5 时用生产 DDL 的主机 SQLite 补充验证；zsh 脚本必须交给 zsh 语法检查；历史 UI XML 尾随日志不能当完整 XML。先区分工具、夹具、证据包装、陈旧断言与真实回归，再处理。

依据：[FTS 迁移测试](../app/src/test/java/com/nanzhufeng/ai/data/LocalContextFtsMigrationContractsTest.kt)、[核验摘要](review/20260910/verification.json)。跨环境结果仍需标注适用范围。

### 11. 状态查询不应顺便读取秘密

presence 只判断凭据状态；授权执行／显示时才读取 secret。用户拒绝、系统不可用、真正不存在分开表达，不因弹窗拒绝就删除凭据或后台循环请求。可用于桌面密码库、硬件安全模块和账号令牌管理；各系统 API／ACL 不通用。

依据：[Desktop 凭据 owner](../desktop/src-tauri/src/desktop_model_service_v1.rs)。

### 12. 文档与流程各有一个权威位置

固定 AGENTS 只放每次开发必守规则；Skill 放可重复流程；合同放当前行为；交接放动态证据；决策日志记录原因；完整档案总结项目；经验文档讲可复用方法。旧版本仍在 Git，不要把历次“当前”叠到入口。

依据：本次 [冲突裁决](南枫AI完整开发档案.md#11-文档代码冲突裁决)、`dd3a445`／`ef76fc4`。当前仓库仍有旧注释和历史审计漂移，分层能降低误用，但不能自动修复所有旧文档。

## 三、不可直接照搬的部分

| 不直接复制 | 原因 | 移植前应验证 |
| --- | --- | --- |
| 15 分钟恢复窗、36–190px Composer、主题色／图标尺寸 | 产品选择而非通用正确值 | 用户流程、字体、辅助功能与平台输入行为 |
| 模型名称、能力、端点、输出预算和价格 | 外部供应商会变化，且单次预算不同于目录上限 | 官方资料、当前目录、请求协议、实际返回及费用 |
| Android schema 66／Desktop user_version 38 | 是本仓库迁移历史，不是行业模板 | 新项目自己的 owner、历史库与连续升级路径 |
| 本机备份文件或 Room 表直接拿去跨端恢复 | 平台内部状态与可迁移语义不同 | 显式映射、缺失拒绝和目标端事务 |
| 无条件重试、通用 fallback | 可能重复收费、换接收方或覆盖未知结果 | 幂等键、可查询回执及本次授权 |
| 直接移用主设备安装命令／签名配置 | 同签名 Debug 仍可能覆盖正式数据 | 包名、Debug 标识、版本、证书及用户授权 |
| macOS 凭据／Apple Development 签名当 Windows 或正式发行方案 | 当前非 macOS secret 读取未接通，开发签名不等于公证分发 | Windows 凭据与安装器；平台签名、更新与分发证据 |
| 把静态 Supabase 测试当安全部署证明 | 测试只检查 SQL 文本和策略，不运行生产 RLS | 本地／隔离 Postgres 与真实部署后的跨用户负向测试 |
| 用大文件实现作为框架模板 | lib.rs／Compose 主文件已形成维护债务 | 按边界提取，而非整文件复制或无基线重写 |
| 直接复制历史“已闭环”结论 | 结论绑定版本、环境和特定状态 | 当前代码是否变化、原始证据是否可读、未验项是否仍存在 |

## 四、复用时的最小流程

确认新项目目标与数据所有权 → 选择上面确实适用的原则 → 找现有 owner → 写一个可观察的失败／成功场景 → 实现最小变化 → 独立验证持久化与外部副作用 → 记录事实、边界和恢复路径。只把多次会用的方法写入 Skill，不把本轮测试数、路径、产物 hash 或未验证猜想升级为长期规则。
