# GLM-OCR 南枫转写当前合同

日期：2026-08-30
状态：Android 已实现；Desktop 已具备本机 owner 与宽屏工作台；真实 Provider 结果仍须单独授权验收

## 1. 产品位置

- GLM-OCR 是文档转换工具，不是聊天模型。它不得出现在 Composer 底部模型选择面、Auto 路由、普通聊天或定时任务模型候选中。
- Android 左侧栏在“定时任务”正下方提供唯一入口“南枫转写”。功能页顶部同步使用“南枫转写”，并在页面可用宽度内居中；页面采用现有南枫工作台视觉，不新增 Composer 常驻按键。
- 设置 → 模型与联网 → 模型设置在智谱服务下正常展示 GLM-OCR 能力，复用同一份本机加密智谱 API Key；聊天默认预设仍只能选择聊天模型。

## 2. 页面与交互

- 主页是从透明系统状态栏后方一直铺满到底部的亮白内容面，亮色外观下状态栏时间、信号和电量使用统一深色图标。内部直接呈现完整 Markdown 转写列表，不再放置“Markdown 结果”重复大标题、说明小字或随内容高度变化的独立白卡，也不再并列显示常驻上传区。每条列表保留 `原始来源 → 结果文件`、状态、页数、Token、可得时的人民币估算和更新时间；不对条目做前 30 条截断。
- “选择图片或 PDF”是主页底部独立悬浮按钮，不进入 Composer，也不使用额外底托。入口只接受 JPG、PNG、PDF；选择后只复制到应用私有目录，不自动外发，并直接进入该条任务详情。
- 选择文件后只保存本机私有副本，仍停留在待转写详情；用户明确点击“开始转写”才是本次发送给智谱 GLM-OCR 的授权与排队入口。不再叠加勾选确认，也不得在选择文件后自动外发。
- 点击任何转写条目进入详情页。详情页只保留两个主内容：可点击打开的“原始文件”，以及生成的 Markdown 文件。原始文件每次打开前须重新完整性校验，并复用对话与搜索的同一私有附件预览投影：图片在 App 内缩放／拖动，PDF 在 App 内翻页／缩放并记住页码；不再通过 `ACTION_VIEW` 、FileProvider 或第三方 App 打开。PDF 卡点击后必须立即打开共享查看器的加载态，不等首页栅格化完成才导航；转写与对话／搜索的 PDF 阅读都使用有界页缓存、相邻页预取和请求代际保护，明确翻页永远优先，旧结果不得覆盖新页。打开成功不在详情页遗留“正在阅读…”信息条，失败仍显示真实错误。
- 每一级页面共用同一返回 owner：详情页的顶部返回、系统返回和左右边缘向内滑动都回到转写列表；列表页的三种返回方式都回到会话页并直接展开左侧栏。返回只改变导航层级，不删除任务或结果。
- 已完成任务的 Markdown 在详情页按块惰性呈现全文，不设 200,000 字符预览上限，不再使用预览弹窗或“已截短”假完整状态。
- 长按已完成结果打开简洁弹窗；“在新对话中继续”创建真实新对话，并把对应 `.md` 文件作为未发送附件加入 Composer 草稿。该动作不自动发送消息。

## 3. 调用、持久化与失败语义

- 只调用智谱固定官方接口 `POST /api/paas/v4/layout_parsing`，模型固定为 `glm-ocr`；不接受用户自定义 URL，不读取当前聊天模型。
- 文件通过已校验的应用私有流分段 Base64 写入请求，不在内存构造完整 Base64 字符串，不记录凭据、请求正文、原始响应或布局明细。
- 完整 Markdown 保存为应用私有 `text/markdown` 附件；任务只保存来源／结果引用、请求 ID、页数、Token、费用估算、安全错误码与时间。
- 每次 GLM-OCR 的真实尝试或发送前门禁都写入既有统一调用账本，不另建只供页面展示的记录。“费用与用量”页在累计、上方汇总和第四个“南枫转写”切换项中读取这些记录，按现有格式显示状态、服务商、模型、完成时间、耗时、Attempt 数、输入／输出 Token 和人民币费用；调用详情额外从任务 owner 关联显示原文件名、页数、服务商请求 ID 与安全错误码。账本不保存文件内容、Prompt、请求／响应正文、Key、URI 或私有路径。
- 图片上限 10 MB，PDF 上限 50 MB；超限文件立即拒绝并清理本次私有副本。返回体使用独立 32 MB 上限，避免把聊天回复上限误套给长文档。
- WorkManager 以任务 ID 建立唯一后台任务。网络未知或超时不得自动重试，以免重复计费；页面只在用户明确点击后重试。异常退出后的 `PROCESSING` 任务允许由同一持久任务恢复执行。
- 本机备份包含 Room 任务表和既有 `attachments/v1` 私有文件；全量本机数据删除同时删除任务与附件。附件仍被 OCR 来源、结果或对话草稿引用时不得清理物理文件。

## 4. 跨端与验收边界

- Android：已具备列表首页、悬浮文件选择、持久任务、后台执行、原文件安全打开、完整结果详情和新对话草稿附件 owner。
- Android 全屏本地搜索把每条转写的原始 JPG／PNG／PDF 和已生成 `.md` 纳入既有“全部／图片／文件”结果面；文件名可搜索，Markdown 正文通过已校验私有流逐行匹配而不建立第二份正文索引。默认搜索排序不再生成单独的“南枫转写”区块，原文件和结果按各自真实时间混入普通附件的年月时间线。点击任一结果直接打开对应南枫转写任务详情，继续使用其中的原文件和 Markdown 文件 owner。
- Desktop：已具备图片／PDF 私有导入、固定 GLM-OCR 请求、分段 Base64、32 MiB 返回上限、持久任务、详情字段投影、取消／重试、Markdown 预览／导出与继续对话 owner；宽屏保留任务列表／详情双栏。Provider 请求 ID、页数、Token、人民币费用与安全错误码只显示真实持久事实，不用占位值伪造。
- Desktop 本机验收可覆盖文件选择取消、凭据缺失、持久任务状态、详情投影和重启回读；未经单独授权仍不得发送真实文档给智谱，因此真实页数／Token／账单／长文完整性继续属于外部 Provider 验收。
- 自动验收覆盖目录隔离、固定接口／分段 Base64、来源结果映射、统一调用账本、搜索目录与详情定位、Room `61→62` 迁移、备份迁移链、超限清理、未知结果不自动重试，以及新对话附件续用。
- 未经用户单独授权不得用真实 API Key 发起 GLM-OCR 请求；构建或假 transport 通过不能替代真实 Provider 结果与设备视觉验收。
