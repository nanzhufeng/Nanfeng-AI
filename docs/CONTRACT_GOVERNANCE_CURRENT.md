# 全项目合同治理与当前口径

适用南枫 AI Android／Mac及仓库独立协议／服务。当前功能不因文档整理改变。按[领域索引](contracts/CONTRACT_INDEX.md)定位入口；机器登记表为protocol/contracts/contract-registry-v1.json，不再由“CURRENT”、文件日期或阶段编号猜优先级。40领域的现行实现定位见[owner索引](contracts/DOMAIN_OWNER_MAP.md)；它只提供代码入口，不新增第二套业务规则。

## 事实与规则层级

用户当前明确要求及项目AGENTS约束执行范围。判断软件事实时，当前源码与适用验证优先；领域合同规定当前语义，专项子合同只约束自身owner／格式／场景，旧验收只证明旧阶段，不能当新的网络或安装授权。

| 分类 | 含义 | 维护方式 |
|---|---|---|
| CURRENT | 现行应用领域语义 | 更新正文与对应生产owner／行为测试；保留历史状态日期 |
| SCOPED | 独立模块、格式或平台的限定规则 | 本模块的类型、事务与隐私边界仍有效；不将“仅本地／未联网”扩展到整个软件 |
| HISTORICAL | 旧阶段一次执行、准备或交付事实 | 保留版本与证据；不用于复用旧令牌、恢复旧限制或判断当前是否接入 |
| EXPERIMENTAL | 本地harness／独立实验能力 | 源码可能存在或已接入只读页面；不自动开放Provider、Agent、跨应用或其他外部副作用 |

索引中的领域入口是第一阅读点，不是抹除所有子合同。UI、数据库领域、协议格式与验证报告各自分层，多个格式子合同不可互相替代。相同名称或表面不意味着Android与Mac共享数据库、权限或验收；平台差异必须注明。

## 已统一的关键口径

- 普通／工作生成、临时本地消息、辅助检索、OCR、导入、Compare历史分支、Agent本地实验是不同用例。模型源代码存在不等于临时聊天或Agent可以外发。
- 正常生成已由实际执行器／Adapter／持久owner实现；早期P2／P3的Disabled、DryRun或本地USER记录仅描述当时模块，不把整机改回未联网状态。
- 已选对话日常同步为direct、Google账号／HTTPS／账号与区域隔离；旧加密封包、恢复码、READY和方向规则只适用于旧格式与隔离模块，不作为当前登录同步资格门。附属兼容记录与全量设置同步分开。
- 手选／Auto、返回模型／请求模型、当前默认／旧精确ID、历史授权读取／新发送许可分开。现用模型清单／菜单层级和单模型差异只看模型维护入口。
- CHAT与WORK独立；草稿、临时记录、正文、附件与同步选中集合不得按页面显示或旧schema猜配。Schema数字是迁移或历史阶段事实，不是当前全库版本常量。
- 前台生成岛隐藏、后台默认简洁、终态有限显示；显示只读持久事实，不产生网络重放。旧前台操作岛、旧收起按钮或未实现暂停不恢复。

具体规则分别归领域合同，本页不复制完整参数、UI尺寸、迁移字段或模型价格。当前设备、服务、构建、安装及未验项只写PROJECT_STATUS／CURRENT_HANDOFF，不放进登记表作为永久真值。

## 日常修改与升级

1. 先在索引找到领域入口及受影响子合同。明确平台、对象、写入／读取／外发与历史兼容范围。
2. 对照当前owner，直接修改冲突正文；将旧章节标为历史，不靠顶部新说明掩盖正文仍声称“当前”的矛盾。保留原文件名、历史字段、验收和证据，避免破坏外部引用。
3. 新合同先登记路径、领域、分类与精确范围；新领域只能指定一个第一阅读入口。独立子owner／格式可以并存，但不能定义第二套同名字段真值。
4. 修改规则若涉及业务行为，连带改owner、迁移／历史读取及行为测试；仅文档修正则验证业务输入hash未变。纯合同整理不借机重做UI、状态机或数据库。
5. 生成与只读检查：

```sh
python3 protocol/scripts/verify-contract-governance.py --write
python3 protocol/scripts/verify-contract-governance.py
python3 protocol/scripts/audit-contract-consistency.py --write
python3 protocol/scripts/audit-contract-consistency.py
python3 -m unittest discover -s protocol/tests -p 'test_contract*.py'
python3 protocol/scripts/verify-model-service-contract.py
```

写入命令只生成登记合同的适用口径与索引，不改正文业务语义；删除、未知路径、重复领域、历史主入口或断链先失败，不能用脚本自动裁决冲突。每个合同头必须显示登记表适用范围。移动实现或增加领域时更新`contract-owner-map-v1.json`；新增旧规则回归检查只约束已复核的具体断言，不能用关键词扫描代替新语义裁决。历史规则用明确的历史父章节包含子章节，不让同级标题逃出历史范围；原有文件名、协议字段、证据和引用锚点保持可读。修改模型还须按[模型维护流程](model-service/MODEL_SERVICE_MAINTENANCE.md)验证。

## 现行测试与交付入口

设备隔离、正式签名凭据、安装授权及数据保留只读取项目[AGENTS](../AGENTS.md)和[测试交付流程](../.agents/skills/nanfeng-ai-testing-delivery/SKILL.md)。合同旧阶段的版本/code、固定模拟器序列号、ad-hoc产物和一次退出门只属于当时证据，不能成为后续升级的签名、设备或安装要求。未来验收使用当次隔离环境；模拟器可操作不授权主设备测试，历史真实链路成功也不授权重发UNKNOWN或抹去新的真实验收缺口。

维护扫描须识别带序号／日期前缀的明确历史章节，并保持同级当前章节重新生效；日期本身不能把当前义务变成历史。原有标题可作为历史父章节的子标题保留，标题层级变化不改变旧链接slug。历史结果与协议／数据格式边界分开：归档一次交付证据不删除仍在用的兼容字段或迁移约束。

## 实现变更后的逆向合同复核

代码checkpoint先核对版本控制集合：生产owner、参数配置、资源、Schema、共享fixture及依赖测试完整纳入，不能依靠未跟踪文件构建通过；原始服务回执、临时before／日志和私有材料不混入提交。合同正文只修正已核实的实现差异，测试结果、commit/tag和排除集合写当次验证报告与状态文件。提交／本地门禁不关闭真实验收缺口，也不授权推送、发布或安装。

发布、路由、材料解析、计量或UI状态修改后，从owner map反查同一领域的CURRENT和SCOPED合同；只更新主入口而保留子合同的旧“当前能力”仍是冲突。逐项核对接收方、字段来源、原币与显示投影、序列化/适配器接线及终态，不用发布日期或类名存在代替结论。

- UI合同持有入口、状态文案与布局；Provider参数、附件转换和费用运算只引用各领域权威正文，避免复制每个模型的协议参数。
- 纯mapper／serializer／默认disabled接口可以已被外层adapter接线：分清“自身不访问网络/SAF/数据库”与“没有生产消费者”，不要把模块边界扩大成整机能力结论。
- 双端现有实现有差异时明确列出；文档整理不偷偷改行为以制造一致。历史反馈／验收放在显式历史父章节下，保持旧状态和标题锚点，不继承旧设备授权或把旧OPEN改为CLOSED。
- 已裁决的具体旧条款加入离线审计回归哨兵，验证当前违规会失败、历史原文可读、合法限定owner不误报。哨兵不是自然语言全语义证明；没有命中的新冲突仍需要沿实际owner裁决。

## 检查边界

全量清点、元数据、引用与语法扫描不等于每一句规则都经过完整代码／服务证明。口径门禁防止漏登记、双重入口、范围标签和索引漂移；语义冲突仍沿具体输入→用例→持久化→读取→界面查证。历史截图、原生XML、包及记录保留原样，格式问题不能通过改历史证据来消失。

报告区分：结构／引用检查、热点语义复核、行为回归、构建、原生、真实服务与部署。文档/维护审查不安装、不清数据、不读Key、不调用用户材料或远端服务；“不安装”指真机，模拟器按当前任务范围自主操作，不重复询问安装许可；长期主设备隔离仍由AGENTS管理。
