# 南枫 AI Android → Desktop 双端同步审计（2026-08-31）

## 结论

当前审计只以 checkout 中 Android live source 与当前合同为功能、文字、排序、控件和行为基线；`f596b8b` 仅保留为历史记录，不能再决定 Desktop 当前实现。Desktop 已完成第一批可独立验收的同步，并在设置 IA、模型服务设置、本机数据治理和本机备份／恢复上继续推进。

**双端全部功能尚未完成同步。** Desktop 当前仍没有普通聊天的真实 Provider 执行链、Android 同级的后台／多会话生成连续性、Google 账号与端到端加密同步、计划任务通知，以及完整的用量费用闭环。这些能力不能用静态按钮或假状态替代，必须按 owner 分阶段接通和验收。

## 对齐原则

- Android 决定功能语义、状态边界和失败行为；Desktop 只因宽屏、键鼠、原生文件选择器等平台差异调整布局和输入方式。
- 本地设置与收藏仅保存设备外观偏好和不透明会话 ID，不进入跨端业务数据合同。
- 导出只包含可见正文和安全附件元数据，不包含推理、凭据、私有路径或内部诊断。
- 缺少真实 owner 的功能保持显式未接通，不伪造“已同步”“已完成”或生成结果。

## 仍需同步的 Android 能力

| 优先级 | 能力 | Android 基线 | Desktop 当前缺口／下一 owner |
| --- | --- | --- | --- |
| P0 | 普通聊天与模型服务 | 真实 Provider、模型路由、流式持久化、重试／停止、退役模型失败关闭 | Desktop 仍以本地工作台／比较流程为主；需接入凭据门禁、Provider executor、流式消息持久化和旧会话归因，未接通前不得把按钮称为普通聊天完成 |
| P0 | 生成连续性 | 单会话与多会话独立生成，切页／后台不中断，停止当前／停止全部，进度与未读投影 | Desktop 缺任务注册表、后台 owner、恢复和通知；需先定义跨窗口／进程退出边界再实现 |
| P0 | 账号与南枫云 | Google 账号、恢复码、端到端加密同步、账号切换与真实状态 | Desktop 只有局部状态或占位链；需接生产认证、密钥派生／恢复、冲突和删除语义，并做双设备真实账号验收 |
| P1 | 上下文能力 | 个性化、Memory、资料库、历史对话、搜索附件按合同投影到请求 | Desktop 有本地内容与部分检索能力，但尚未连接到真实普通聊天请求；需保证来源可解释、失败关闭与删除一致性 |
| P1 | 附件外发 | 多格式本地完整性、预览、解析、模型能力门禁、实际请求投影 | 本轮只完成草稿／会话预览复用；多模态 Provider 外发和不支持模型提示尚未闭环 |
| P1 | 用量与费用 | 请求归因、Token／价格完整时估算、健康与失败审计 | Rust 有账本基础，但普通聊天尚未写入完整用量，Desktop 缺面向用户的完整统计页 |
| P1 | 计划任务与系统通知 | 计划任务、后台执行和明确通知 | Desktop 尚无对应真实调度与通知 owner |
| P2 | 语音与转写 | Android 语音输入／转写能力及其模型资产合同 | Desktop 尚无同级录音、权限、转写生命周期和缓存合同 |
| P2 | 批量数据治理 | 归档、回收站、恢复、彻底删除及附件引用计数 | Desktop 已有单项生命周期和跨端包能力，但仍需逐项核对批量操作、最后引用清理和异常恢复 |
