# 南枫 AI 开发路线与产品架构思路

## 一、核心判断

南枫 AI 第一阶段应采用：

> **移动端优先，但架构从第一天支持桌面端。**

不是简单开发一个手机 App，而是构建：

> **个人 AI 操作系统入口：连接个人数据、知识资产、AI 模型和自动化能力。**

核心目标：

- 让 AI 进入日常生活流程
- 降低信息记录成本
- 自动沉淀个人知识资产
- 连接南枫系软件生态
- 逐步形成个人 AI Agent 系统

---

# 二、为什么优先手机端

## 1. 南枫 AI 的核心价值是“随时捕获”

未来高价值场景不是：

“用户坐在电脑前打开 AI”

而是：

“用户遇到任何信息，立即交给 AI。”

例如：

- 看到投资新闻 → 分享给南枫 AI
- 看到视频 → 自动转文字分析
- 突发想法 → 语音记录
- 拍摄资料 → OCR识别
- 浏览网页 → 自动收藏分析


手机天然适合作为：

- 信息入口
- AI入口
- 生活入口

---

## 2. 高频使用比复杂功能更重要

电脑端优势：

- 大屏
- 多窗口
- 文件管理
- 数据分析
- 高级配置

但是使用频率较低。

手机端优势：

- 随时打开
- 快速输入
- 快速反馈
- 高频触达

对于个人 AI 系统：

> 高频使用产生的数据积累，比初期复杂功能更重要。

---

# 三、为什么不能简单电脑优先

虽然电脑端功能复杂度更高：

包括：

- 知识库管理
- Agent流程设计
- 模型配置
- 文件处理
- 数据分析
- 工作流管理

但是：

复杂功能不等于优先级最高。

电脑更适合作为：

> AI控制中心

而不是：

> AI入口。

类似：

## 手机

负责：

- 输入
- 捕获
- 查询
- 快速决策


## 电脑

负责：

- 管理
- 分析
- 配置
- 深度生产

---

# 四、整体产品架构

采用：

## Core + Client 架构

```
                南枫 AI Core

                    |

        ---------------------------

        |                         |

   Mobile Client            Desktop Client

        |                         |

   快速入口                  管理中心

   AI对话                    工作流管理

   语音输入                  知识库编辑

   图片/文件                 数据分析

   分享入口                  模型配置

   快速记录                  Agent调试
```

核心原则：

> 数据、AI能力、知识资产属于 Core，不属于任何客户端。

这样未来可以扩展：

- Windows
- macOS
- Android
- iOS
- Web

---

手机 MVP 稳定后，开发：

## 南枫 AI Desktop / Web

定位：

AI控制中心。


主要功能：

## 1. 知识管理

包括：

- 浏览知识库
- 搜索
- 编辑
- 标签管理
- 时间线管理


## 2. Agent 工作流

例如：

投资分析流程：

```
新闻输入

↓

AI整理

↓

关联公司

↓

估值模型

↓

生成投资判断

↓

记录投资日志
```


## 3. 模型管理

包括：

- API配置
- 本地模型
- Provider管理
- 成本统计

# 七、技术路线建议

## 前端

优先：

React Native + Expo

原因：

- 与现有 React / TypeScript 技术体系一致
- 跨平台能力强
- 后续维护成本低


桌面端：

优先：

Web/PWA

后续：

Electron 或 Tauri。


---

## 数据层

坚持：

本地优先。

建议：

```
SQLite

+

本地文件系统

+

可选云同步
```

原则：

- 不强制云端
- 不绑定单个平台
- 数据用户掌控

---

## AI层

采用：

```
南枫 AI Provider Framework

                |

--------------------------------

GPT

Claude

Gemini

DeepSeek

Ollama

本地模型
```

每个软件可以独立运行：

- 有自己的 AI Provider Framework
- 南枫 AI Hub 作为增强层

避免所有软件强依赖中心服务。

# 九、需要避免的方向

## 1. 不做简单聊天壳

原因：

容易被通用 AI 替代。

---

## 2. 不一开始堆复杂 Agent

原因：

没有数据积累，Agent价值有限。

---

## 3. 不做强云端依赖

原因：

长期维护成本高。

---

## 4. 不同时开发多个客户端

原因：

降低迭代速度。

---

# 十、最终战略定位

南枫 AI 的核心不是：

“做一个 AI App。”

而是：

> 建立一个属于个人的数据、知识和决策系统。

产品路线：

```
手机：
AI入口

↓

知识沉淀

↓

桌面：
AI控制中心

↓

Agent自动化

↓

个人AI操作系统
```

最终目标：

让 AI 成为个人长期成长体系的一部分，而不是一次性工具。
