# 南枫 AI Android 当前普通聊天运行时上下文合同

日期：2026-09-01
状态：**当前有效；普通聊天向任一已选模型发送前的个性化、Memory、资料库与历史对话上下文唯一正文**

## 1. 范围与优先级

本合同只约束 Android 普通聊天的实际发送前上下文组装链：`NormalChatOpenRouterExecutor → LocalContextBroker → ChatAdapter`。所有模型选择共用这条上下文组装链；更换 Provider 或模型只改变实际执行 Provider／模型与预算，不改变资料来源边界。

发生冲突时，优先级固定如下：

1. 当前源码中的上下文组装链及本合同。
2. [Android 当前设置界面合同](ANDROID_SETTINGS_UI_CURRENT_CONTRACT.md) 的用户可见开关、文案与编辑规则。
3. [Android 当前会话与搜索界面合同](ANDROID_CONVERSATION_UI_CURRENT_CONTRACT.md) 的会话可见规则。
4. `P4-*`、`domain-rules.md`、`implementation-plan.md`、`architecture-governance.md` 与旧交接中的 P4 阶段描述：只保留当时的显式本机预览／未接普通发送证据，**不得**反向声明当前普通聊天“不会自动加入上下文”。

“自动”只指用户已经开启相应开关后的本机相关性检索；它不等于自动写入 Memory、自动上传整个资料库，或绕过一次普通聊天的既有发送确认、Provider／模型与费用边界。

## 2. 用户资料与语气：每次普通调用均适用

- `personalizationEnabled=true` 时，用户自己填写的昵称、职业／角色、关注方向与自定义指令作为个性化要求加入**每次**普通模型调用；这不是检索型长期 Memory，不受长期 Memory 是否暂停影响。
- 当前基础风格和语气进入每次普通调用的唯一 `system` 指令，不依赖个性化或记忆开关。它只改变表达方式，不改变模型、联网、记忆或资料库开关的功能语义。六个可见风格按“默认、直言不讳、专业可靠、亲和友善、高效务实、风趣搞笑”排列并使用稳定 ID；“默认”是可选择的中性风格，使用自然、清晰、按任务复杂度调整详略的指令。当前会话快捷覆盖高于设置全局值；没有覆盖时继承设置里当前选中的风格，无法识别的会话覆盖值也按“无覆盖”处理，不得强制改成默认。普通发送、带 OCR／文本投影的附件发送、官方网页检索、失败重试与旧会话继续全部在 `requestOne` 开始时重读这个最终值，不固定为会话创建时的历史风格，也不得重复注入。
- 填写昵称后，新对话首个成功助手回复必须自然以该昵称开头；普通请求层先提示该规则，并在成功输出落库前以同一 Provider 无关的展示兜底补齐，避免任一模型遗漏。用户当前消息明确要求其他称呼时，以当前消息为准。
- `personalizationEnabled=false` 时，不注入昵称、职业／角色与关注方向；已选风格和已保存的自定义指令仍按它们各自的独立设置参与表达。自定义指令是用户明确写明“用于所有南枫AI对话”的偏好，不能被记忆检索开关误关掉。

## 3. Memory、资料库与历史对话：原始层、二次整理层与最小发送

全部历史对话是本机保存、可回溯的原始层；资料库是从这些历史和用户明确保存的资料中沉淀出的二次整理层，不是原始对话的替身。`LocalContextBroker` 在本机提取当前问题的检索词、按当前会话／项目范围查询并排序；优先将最终选中的已确认资料库／Memory 条目随本次请求发送，只有资料层没有相关内容或预算仍有余量时才补入原始历史片段。它不会把整个本地索引、完整历史、附件字节、凭据、运行日志、工具输出或同级分支外发。

历史整理保留两条路径。手动路径由用户在资料库中对当前已选对话明确发起：确认前，App 展示将发送的文字范围与固定模型顺序；确认后，模型仅生成可编辑的候选，用户再次确认才写入资料库。手动与自动路径均与会话标题整理共用 `DeepSeek V4 Flash → GLM-5.3 Flash → Qwen3.6 Flash` 顺序：仅跳过未启用、缺少凭据、模型不可用或本次失败的前置项，千问始终位于最后兜底。每次真实请求均按实际服务商、模型和推理档位写入无正文本机审计；GLM 继续明确使用 `max`。自动路径与资料库检索由同一个“历史资料库”开关共同控制：只有用户开启后才允许低频自动整理和普通聊天的相关资料调用；关闭则同时停止两条链。旧版独立的“调用已开、自动整理未确认”状态安全迁移为关闭，绝不因升级自动外发。自动路径只在对话静置后和低频后台窗口运行。12 小时周期必须保留原计时基点，不得因 Activity 或 `AppContainer` 重建而重置；系统在 App 冷进程直接唤起 Worker 时，必须能通过 `Application` 的惰性 `WorkManager` 配置完整启动，不依赖 Activity 先打开。本机仅用最小轮次、文本长度、当前分支、来源哈希和已有来源去重节省 Token；是否有长期价值必须由模型判断，且只有高置信结果才自动写入。自动路径每次最多发送当前分支 6,000 字文字、最多请求 768 输出 Token，不发送附件、工具内容、其他对话、完整历史、凭据或调用正文；每 12 小时最多选一条旧对话进入真实模型路由，模型判定不适合后本窗口立即结束，不继续外发下一条。长对话保留首尾内容以让新增结论重新进入版本哈希；对话正文一律视为不可信引用，只有用户明确表达或确认的内容可以入库。来源引用、规范化内容哈希用于阻止自动重复；Provider 调用前必须先持久化来源预留。已知失败可按安全码重试；中断后仍处于预留态的来源必须转为 `UNKNOWN`，不得自动重发。高相似但不能证明相同的内容只加“可能重复”标记，绝不静默丢弃。只有超时、网络、408、429 或 5xx 才可后台重试。每个到期窗口都写入无正文运行终态和安全原因码；未选中候选、未配置模型或冷进程调度失败都不得伪造 Provider 调用、Token 或费用。候选必须保留本地会话引用、实际服务商、实际模型与“历史对话自动整理”来源；原对话不被改写，资料条目可编辑、归档或删除。

投资决策类问题（证券／基金／指数与买卖、估值、仓位、配置相关表达）在“启用记忆”时默认扩展本机检索词，以优先召回投资体系相关 Memory；资料库搜索开启时也检索相关资料库。它不绕过用户关闭的记忆或资料库开关。当前会话的“实时网页搜索”一旦开启，本次普通对话必须走已支持的官方实时检索路由，不再以输入框关键词猜测是否需要联网；附件中的行情、政策、财报或其他当期事实同样适用。

| 来源 | 生效条件 | 范围与上限 | 不加入的情形 |
| --- | --- | --- | --- |
| 长期 Memory | `memoryEnabled=true`（即个性化和记忆检索均开启） | `ACTIVE` 的全局／当前项目／当前会话 Memory；本机相关性检索至多 6 条 | 开关关闭、暂停／删除、范围不匹配、无相关命中、索引不可用或超出本次预算 |
| 资料库（二次整理层） | `historyLibraryEnabled=true` | `ACTIVE` 的全局／当前项目 Knowledge；本机相关性检索至多 8 条，优先占用检索预算 | 总开关关闭、归档／删除、范围不匹配、无相关命中、索引不可用或超出本次预算 |
| 原始历史对话 | 普通聊天默认可用 | 当前会话此前路径至多 24 条；当前会话以外的本机历史索引至多 8 条，仅作资料库不足时的补充 | 草稿、软删除／归档内容、兄弟分支、附件／工具正文或超出本次预算 |

所有来源共同去重并遵守当前模型的 token 预算；若单条已超预算，整条不发送，禁止字符级截断后伪装为完整资料。检索、排序、去重和预算裁剪都发生在设备本机，Provider 仅收到已选出的最小必要文本。

Provider 返回的独立 reasoning／analysis 仅作为本条 Assistant 回复的本地折叠阅读内容保存；它不属于用户可见最终答复，也绝不回送进后续上下文、Memory、资料库、原始历史索引、自动标题、复制或普通导出。

千问模型的当期事实联网使用官方 Responses `web_search` 路径，普通聊天必须以语义 SSE 消费：只有 `response.output_text.delta` 可进可见正文，搜索／工具状态与原始载荷不得显示或持久化；只有 `response.completed` 才是完成事实，`failed`、`incomplete` 或无明确终态的 EOF 均不得把部分文本写成完整回复。Provider 返回的结构化公开来源在同一终态合并进最终可见文本。请求明确 `store=false`；单次无数据读取窗口 180 秒，整体流生命期最多 10 分钟，超时仍作为结果未知且不自动重投。

## 4. 设置与用户可见说明必须一致

- “启用记忆”开启后：资料、Memory 与资料库均按本合同参与普通聊天；关闭后不检索或发送长期 Memory，但资料库开关和当前对话历史的各自规则不变。
- “历史资料库”是自动沉淀与普通聊天检索的唯一总开关。关闭后取消后续后台整理且普通聊天不检索或发送资料库片段；已保存资料、用户资料、长期 Memory 开关和原始当前对话历史均不受影响。
- Memory 必须由用户显式创建、确认或更新；“自动检索相关 Memory”绝不等同于“自动创建／静默保存 Memory”。
- 记忆摘要页的“询问摘要”只查本机，“补充记忆”只在用户显式选择后写入本机；该页输入不隐式调用模型或外发。“编辑摘要”的全文替换同样只在本机提交；新全文与旧 ACTIVE 全局摘要的软删除在同一事务完成，后续检索只读替换后的 ACTIVE 内容，已删除修订不重新成为检索材料。
- “关闭记忆摘要生成和应用”只将 `memoryRetrievalEnabled` 关闭：后续“记住了”不会触发摘要生成，聊天尾部不再显示“加入记忆摘要”，普通聊天也不会检索或发送长期 Memory；昵称、职业和自定义指令仍按 `personalizationEnabled` 的独立规则参与。该关闭不删除现有摘要；“删除记忆”只软删除摘要，不反向关闭上述开关。
- 所有可能与本合同有关的设置、小字、空态和说明不得出现“长期 Memory 必须显式创建，且不会自动加入上下文”或等价断言；应明确“显式创建后，在开关开启时按当前问题自动检索相关内容”。

## 5. 回答级来源说明

- 每条成功落库的普通 Assistant 回复，必须按其**实际发送 Attempt**绑定本次上下文选择；不能按当前设置、当前模型或之后的再次检索倒推来源。
- 回复三点菜单的“本次回答信息”是唯一回答级解释入口。每条新生成的完整 Assistant 回复随现有模型归因永久保存生成时实际使用的对话风格，以及是否由官方联网路由取得可验证 HTTP(S) 来源；后续改变全局设置、当前会话快捷选择或联网开关都不得改写旧回答。旧记录缺少字段时显示“未记录（旧回答）”，不得推测。实际发送的本地来源继续只显示单行主标题；对话风格改由顶部事实行显示，不在来源列表重复。不得展示任何来源正文、Prompt、附件字节、Provider 原始请求或凭据。
- 没有加入任何本地来源时，“本次回答信息”仍显示风格与实时网络结果，但不显示空的来源章节；“上下文记录”卡也不展示“未加入”或“未检索”行。旧记录只显示已保存事实，不补充推测。
- 审计只在本机保存，且只在真实可见回复落库后绑定；请求失败、取消或未产生 Assistant 回复的上下文诊断不得出现在回答级入口。
- 流式回复的正文完成、自动标题、模型／Token／费用归因与回答执行证据属于主完成链：只有正文未能形成完整本机回复时才标为“回复保存未确认”。流式增量只是生成中的临时可见投影；Provider 分层解码、思考尾字泄漏清理和首条称呼兜底产生的**最终可见正文**，必须作为同一 `RuntimeCompleted` 终态事件的内容原子替换持久化，禁止先用未清理的流文本进入终态，再绕过运行时 owner 直接修改消息。Provider 的 reasoning 是可选折叠补充，必须在该正文终态之后再保存；其单独失败不得撤销正文、标题或费用，也不得阻止用户继续发送同题或新问题。本机完成事实归因失败须单独说明“正文已保存，费用、Token 与回答执行信息待补写”，发送 Attempt 创建失败则明确为“未向服务商发送”。

## 6. 临时聊天隔离

临时聊天不是普通聊天：它使用 `TemporaryConversationId`、`TemporaryConversationDomain` 与独立临时恢复表，最多仅在本机恢复 24 小时。其“发送”只追加本地临时消息，**不连接模型服务**，因此不读取或外发个性化资料、Memory、资料库、普通历史对话、附件正文或当前普通会话路径；也不进入普通会话搜索、自动标题、记忆摘要、上下文记录、费用／用量或普通会话列表。临时恢复不是自动沉淀：到期或明确清理后，临时记录及关联私有附件引用一并删除。

临时／普通之间只能通过用户显式的“返回普通聊天”切换视图；该切换不复制、导入或转换临时内容。任何未来临时发送能力若要改变“不连接模型服务”的边界，必须先单独定义用户确认、上下文、外发、留存与验证合同，不能复用普通聊天默认值。

## 7. 真实所有者与回归门禁

- 设置与资料注入 owner：`AssistantExperienceSettings.modelInstruction`。
- 普通发送开关接线 owner：`NormalChatOpenRouterExecutor`，分别传入 `includeRelevantMemory = experience.memoryEnabled` 与 `includeRelevantKnowledge = experience.historyLibraryEnabled`。
- 本机检索、范围、去重、完整条目预算与来源记录 owner：`LocalContextBroker` 与 `RoomLocalContextIndex`。
- 回答级来源 owner：`ContextSelectionAuditStore` 的 Attempt→Assistant 消息绑定与 `ConversationFoundationViewModel` 的答案投影；展示文案由 `ContextSelectionAuditRecord.answerContextDisclosure` 生成。
- 临时聊天隔离 owner：`TemporaryConversationDomain` 与 `TemporaryConversationIsolation`；它们不持有 `ConversationRepository`、`LocalContextBroker`、普通搜索或自动沉淀 owner。
- 回归至少覆盖：用户资料在长期 Memory 暂停时仍参与调用；两个检索开关独立生效；当前用户消息不因检索关闭而消失；回答级来源只显示实际绑定的本地记录；临时聊天无法走普通上下文／搜索／自动沉淀链；UI 不再出现反向文案；当前合同、设置合同和会话合同都链接至本合同。

这份合同不证明某次第三方 Provider 已成功调用或用户数据已在真机视觉路径验收；它定义的是普通发送前本机组装边界。真实 Provider、费用和真机可见结果仍按各自验收记录单独报告。
