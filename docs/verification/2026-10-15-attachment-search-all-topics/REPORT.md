# 附件不限主题联网修复与双端正式覆盖

截至 2026-10-15T16:32:20+08:00，WORKTREE，底层 HEAD `5a52aa2a8928cc46bad136cb608fd1eb3b62517e`。本轮已实现修复，双端隔离原生 owner 的图片＋文档跨主题真实搜索、正文／来源／金额持久化及重开通过；随后按用户“覆盖安装”授权完成 OPPO／Mac 原签名保数据覆盖。未提交或发布 GitHub。

## 根因与修复

- 无本地文字的媒体曾绕过读取，在模型看到图片前让入口插件检索泛化提问，来源数量不能证明内容相关。现在先由原选模型忠实读材料，再用实质内容查询，保留原件供最终回答。
- Android 读取阶段遗漏流式请求体，仅发送占位字符串；已传递真实 body，并按模型能力处理流式／非流式，成功读取费用进入原调用账本。
- 旧规划会遗漏短中文、单字符及没有日期数字的英文主题；已取消这些主题筛选，并保留隐私与材料指令边界。回归包含印象派、Photosynthesis、文学、禅、C、R及个人材料的去标识主题。
- 普通主题可以返回“已检索”的相关网页资料，事实主张才作真假核验；最终回答得到应用提供的真实搜索执行元数据，不能因没有重复调用工具而否认前序搜索。
- 原附件、提取结果与检索证据分别持有。Mac 不再把提取结果追加为原文件内容；查询批次不再混入“分析两份附件”的最终任务。标签／操作要求不作为主题，明确无关的来源不作支持引用。
- 现行检查点为 v6，旧 v5／v4 不命中，历史回答及费用不回写，UNKNOWN 不自动重发。实际模型、Provider、Key 与既有接收方不变。

当前规则归 [C12](../../C12_MODEL_NETWORK_PARITY_CONTRACT.md)，架构只作路由。
